# Чат-модель Embryo: как она собирается

Запечатанный геном Embryo, записи знаний рядом с ним и резонансный роутер, который выбирает запись. Все шаги лежат в `scripts/embryo/`.

## Обучение (GPU)

Команды те же, что в [английской версии](EMBRYO_CHAT.md#training-gpu): `build_brief_mix.py` режет каждый ответ до первых предложений, `sft-prepare --seq 256`, затем `sft --replay-fifths 2` (3/5 записей чата и 2/5 окон сырого текста, база продолжает учиться). На Mac с 24 ГБ обучение идёт по одному процессу.

Обучение чату изнашивает дальнюю память. Лечение возвращает её, не трогая остальную сеть: `birth --train-only layers.3.attn,layers.7.attn` учит только якоря на окнах сырого текста с задачами на извлечение, все остальные тензоры и дескрипторы маршрутизации остаются побайтно теми же.

## Сборка

`scripts/embryo/assemble_chat.sh <ckpt> <dir>` экспортирует запечатанный геном (`DTYPE`, в релизе q8_2f) с шаблоном чата и настройками генерации в файле (`--chat`, `--sampling`), строит записи, считает φ на GPU и подгоняет роутер. `scripts/embryo/eval_chat.sh <dir>` прогоняет гейты.

## Роутер

`router.phi.pool = key_span`. Движок находит ключ таблицы в сообщении и усредняет скрытые состояния после слоя φ: φ = unit(unit(среднее по токенам ключа) + α·unit(среднее по остальному сообщению)). Каждая запись — изолированное подпространство (среднее и k главных направлений); запрос идёт к записи с наименьшей ошибкой реконструкции, если она обходит подпространство основной сети на величину порога. Кандидаты — только записи, в таблице которых есть этот ключ, а сообщение без ключа идёт в основную сеть без прогона φ.

Сообщение без ключа после реплики с ключом (уточнение) решается на φ = unit(unit(токены ключа прежней реплики) + `followup_alpha`·unit(сообщение)) с порогом `followup_margin`, только для карточек с полями. У этой формы φ свои изолированные подпространства (`router.followup`): уточняющие вопросы о записи против посторонних сообщений с тем же ключом перед ними. Подпространства первой реплики эту форму не видели: простые уточнения проходили в 1–2 % случаев.

Сообщение без ключа и не уточнение решается на φ всего сообщения между двумя подпространствами (`router.keyless`): вопросы о конкретном факте и обычный разговор. Вопрос о факте идёт в запись `dontknow` с честным ответом, потому что своих фактов у сети нет; разговор, просьбы и советы идут в сеть. Запись `--keyless` отвечает карточкой своей первой строки.

Общий набор для подгонки должен содержать обычные фразы с ключами таблицы, с ограничением на ключ: иначе одно частое слово заполнит подпространство основной сети.

## Настройки файла для маленькой модели

`sampling.loop_stop = 1`: ответ останавливается, когда его хвост повторяется (причина `loop`), и в итоговом тексте блок звучит один раз. `sampling.history_turns = 1`: сеть видит только последнюю реплику пользователя, потому что маленькая модель копирует свои прежние ответы. Записи сохраняют память разговора в любом случае.

## Запуск

`cortiq run` и `cortiq serve` запускают файл Embryo на резидентном графе GPU (`CMF_GPU=wgpu`, `CMF_EMBRYO_RESIDENT=1`, на Mac это wgpu поверх Metal), если бэкенд не выбран явно. `CMF_GPU=0` включает путь CPU, текст при жадном выборе тот же. Файл Embryo на CPU считает с активациями float: его роутер подогнан по точному φ, а 8-битные активации других моделей q8 сдвигают φ на 4e-3 (`CMF_SDOT=1` их включает: префилл в 5 раз быстрее, текст другой). Оба пути отстоят от точной арифметики не больше чем на 3e-5.

C ABI (`crates/cortiq-ffi`, на ней стоит мобильное приложение) маршрутизирует реплику теми же вызовами движка, а `cortiq_last_route` называет запись, которая ответила. φ там всегда считается на CPU, что бы ни сказал `cortiq_set_gpu`: на Xiaomi 12 Lite пооператорный путь GPU потратил 235 с на арбитраж первого прохода, а CPU тратит около 100 мс на вопрос.

Матрицы лежат на устройстве в том виде, в каком они записаны в файле: f16 или q8_2f (`gpu_wgpu/embryo_wide.wgsl` вместе с `embryo_wide_f16.wgsl` или `embryo_wide_q8.wgsl`). Токен занимает около 80 шагов ядра, а граница между двумя шагами стоит дороже большинства самих ядер (8 мкс на M4, 5 мкс на RTX 2000 Ada), и GPU загружается полностью только множеством коротких потоков. Поэтому поток проходит не больше 128 значений строки, а частичные суммы складывает следующая стадия нормировки; поле столбцов матрицы q8_2f входит во входной вектор один раз, в стадии, которая этот вектор создаёт, а коды распаковываются как целые; якорь поворачивает запрос и ключи на абсолютную позицию, поэтому в кольце лежат повёрнутые ключи и оценка сводится к обычному скалярному произведению; значения складываются блоками по ключам с весом выше e^-16 от наибольшего; дельта-правило и его нормировка делят одну рабочую группу на голову. Голова читает только кластеры с логарифмом вероятности выше −9,21 (`CMF_EMBRYO_HEAD_GATE`; `-1e30` читает все строки, а строки пропущенного кластера возвращаются как −1e30). `CMF_EMBRYO_WIDE=0` включает путь f32.
