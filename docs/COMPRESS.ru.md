# Сжатие модели под задачу: `cortiq compress`

Одна команда превращает общую модель в специалиста под ваши задачи:

```bash
cortiq compress model.cmf prompts.jsonl model-task.cmf --ratio 0.75
```

- `model.cmf` — исходная модель (f16/bf16 или q8; можно HF-каталог или repo id);
- `prompts.jsonl` — промпты вашей задачи (строка = объект с `prompt` или
  `messages`; формат `calibration_prompts.jsonl` подходит как есть);
- `model-task.cmf` — результат;
- `--ratio 0.75` — степень сжатия: результат весит 75 % исходного (тот же кодек).

Что происходит внутри: учитель отвечает на ваши промпты — по умолчанию сама
модель, а с `--teacher` старшая модель, в том числе через API (см. ниже). По
этим ответам видно, какие нейроны задача использует («засветка»);
неиспользуемые уходят, их вклад переносится в оставшиеся, затем модель
доучивается на ответах.
Квантование — отдельный шаг, если нужен файл ещё меньше:
`cortiq quantize-gptq` или `cortiq convert`.

В процессе видно, что идёт и сколько осталось: номер стадии, её цель,
счётчики со скоростью и оценкой «~N мин осталось». Прерванный запуск
продолжает та же команда — готовые стадии не пересчитываются.

На выходе — `.cmf`, который сразу работает в `cortiq run` и `cortiq serve`,
рядом отчёт о качестве (`model-task.cmf.work/S6.eval/report.md`), в
заголовке файла записано происхождение (`provenance.compress`).

Дополнительные параметры (по умолчанию не нужны):

| Флаг | По умолчанию | |
|---|---|---|
| `--teacher` | сама модель | кто отвечает на промпты: другой `.cmf` с тем же токенизатором или модель за OpenAI-совместимым API (`openrouter:…`, `openai:…`, `api:…`) |
| `--api-base`, `--api-extra`, `--api-concurrency` | —, —, 8 | API-учитель: адрес сервера, дополнительные поля запроса, число запросов одновременно |
| `--gen-max-tokens` | 2048, с API-учителем 8192 | сколько токенов может занять один ответ (с рассуждением) |
| `--gen-samples` | 1 | ответов на промпт |
| `--no-think` | | отвечать без рассуждения |
| `--ffn F` / `--size 12B` | | цель по доле нейронов FFN или по числу параметров вместо `--ratio` |

Вместо промптов можно дать готовые данные учителя (`.tdata`, см. ниже) —
например, ответы старшей модели того же семейства.

**MoE-модели** сжимаются той же командой. Засветка считает, как часто
маршрутизатор выбирает каждого эксперта на ответах задачи; в файл попадают
только эксперты, которые набирают нужную долю маршрутов (порог подбирается
под `--ratio`), маршрутизатор работает среди оставшихся как прежде. Пример
(LFM2.5-8B-A1B, 80 кодовых промптов, `--ratio 0.8`): f16 16.96 ГБ → 13.57 ГБ,
в слоях осталось 20–30 экспертов из 32, test NLL 0.280 → 0.332 (тест из 2
записей — ориентир, а не точная оценка). Лечение для MoE пока не делается.

Проектное ТЗ с обоснованием решений и измеренными фактами —
[`TZ_TEACHER_DATA_COMPRESS.ru.md`](TZ_TEACHER_DATA_COMPRESS.ru.md).

## 1. Данные учителя

### Генерация

```bash
cortiq teacher-data generate TEACHER.cmf PROMPTS.jsonl OUT.tdata \
    [--no-think] [--max-tokens 8192] [--samples 1] [--split 90/5/5] [--seed 42]
```

- `PROMPTS.jsonl`: строка = объект с `prompt` или `messages`, по желанию `id`,
  `category` (по ней стратифицируется сплит), `samples`, `max_tokens`, `meta`.
  Формат `calibration_prompts.jsonl` подходит без изменений.
- Учитель — любой `.cmf` с шаблоном чата. Обычно это та же модель в `q8_2f`
  (самодистилляция) или старшая модель того же семейства, то есть с тем же
  токенизатором. Учитель может быть и моделью за API, см. «Учитель через
  API».
- Рассуждающая модель по умолчанию думает. Граница рассуждения и ответа
  берётся по токену `</think>` точно, без разбора текста. `--no-think`
  включает прямые ответы.
- Если генерация срывается в повтор (меньше 5 % новых 5-грамм в последних
  512 токенах), она останавливается, а запись помечается `usable=false`.
- Прерванную генерацию продолжает та же команда: готовые записи
  сохраняются, недописанный хвост отрезается. Другие параметры в том же
  каталоге команда не примет.
- Сплит делается по промптам: все ответы одного промпта попадают в один
  сплит. Test не используется ни одной стадией сжатия, только итоговой
  оценкой.

### Учитель через API

Старшего учителя не нужно ставить на арендованный сервер: подойдёт любая
модель за OpenAI-совместимым `/chat/completions`. Ответы приходят текстом и
превращаются в токены токенизатором той модели, которую будете сжимать
(`--tokenizer`; в `compress` это сам исходник).

```bash
# OpenRouter (ключ в OPENROUTER_API_KEY)
cortiq teacher-data generate openrouter:qwen/qwen3.8-27b prompts.jsonl task.tdata \
    --tokenizer model.cmf --sampling auto --no-think --api-concurrency 32
# OpenAI (OPENAI_API_KEY)
cortiq teacher-data generate openai:MODEL prompts.jsonl task.tdata --tokenizer model.cmf
# свой сервер: vLLM, SGLang, llama.cpp, Ollama, LM Studio, `cortiq serve`, …
# (ключ в CORTIQ_API_KEY, если серверу он нужен)
cortiq teacher-data generate api:Qwen/Qwen3-32B prompts.jsonl task.tdata \
    --api-base http://gpu-box:8000/v1 --tokenizer model.cmf
# то же одной командой сжатия
cortiq compress model.cmf prompts.jsonl model-task.cmf --ratio 0.8 \
    --teacher openrouter:qwen/qwen3.8-27b --no-think --api-concurrency 32
```

- Ключ читается только из переменной окружения и никуда не пишется. В
  манифест `.tdata` попадают модель, адрес и настройки декодирования.
- Ответы складываются в `OUT.tdata.answers.jsonl` по мере готовности.
  Прерванный запуск продолжает та же команда: готовые ответы повторно не
  запрашиваются и не оплачиваются. В строке прогресса видны скорость,
  потраченная сумма (если сервер её сообщает) и оценка оставшегося времени.
- Рассуждение: с OpenRouter переключается полем `reasoning`, с
  vLLM/SGLang/llama.cpp — `chat_template_kwargs.enable_thinking`. Текст
  рассуждения берётся из `reasoning`/`reasoning_content` или из
  `<think>…</think>` в ответе и ставится перед `</think>`, как его
  продолжает шаблон ученика. Ответ, оборванный лимитом внутри рассуждения,
  хранится как усечённая запись без закрывающего тега и без токена конца.
- Серверы принимают разный набор необязательных полей (`top_k`, `seed`,
  `max_tokens` или `max_completion_tokens`, переключатели рассуждения).
  Поле, которое сервер отверг, отбрасывается один раз с сообщением, и
  работа продолжается. Неверный ключ или модель останавливают запуск
  сразу, без сотни одинаковых ошибок.
- OpenRouter по умолчанию идёт к самому дешёвому провайдеру, который держит
  модель в 8 или 16 битах. У одной модели цены различаются в 2.5 раза, а
  часть провайдеров отдаёт её в fp4. Провайдер каждого ответа записан в
  `meta.provider`. Свой выбор задаётся через `--api-extra`, например
  `'{"provider":{"sort":"throughput"}}'`.
- `--api-extra '{…}'` добавляет поля в каждый запрос; поле со значением
  `null` не отправляется.

Замеры (Qwen3.8-27B через OpenRouter, кодовые промпты):

| | ответов | токенов | цена | время |
|---|---|---|---|---|
| с рассуждением, лимит 8192, 8 параллельно | 12 | 87.6k (9 упёрлись в лимит) | $0.19 | 4 мин |
| `--no-think`, 12 параллельно, любой провайдер | 12 | 22.0k (все полные) | $0.048 | 55 с |
| `--no-think`, самый дешёвый 8/16-бит провайдер | 12 | 20.8k (все полные) | $0.032 | 2 мин |
| `--no-think`, 32 параллельно, любой провайдер | 160 | 419k | $0.91 | 2 мин |
| `--no-think`, 483 промпта × 2, 806 новых (160 из кэша) | 966 (52 упёрлись в 8192) | 1.35M | $2.38 | 15 мин |

**Токенизатор — точно той модели, которую сжимаете.** Модели одного
семейства различаются: у Qwen3.8-27B в `tokenizer.json` на 7 служебных
токенов больше, чем у Qwen3.5-0.8B (аудио/TTS, id 248070–248076), и свой
`generation_config.json` с концом хода `<|im_end|>`. Данные,
токенизированные младшей моделью, S0 отвергнет по хэшу словаря, а ответы
кончались бы не тем токеном. Если самой модели на машине нет, хватит
носителя токенизатора: малая модель того же семейства, в чей каталог
положены `tokenizer.json`, `tokenizer_config.json`, `chat_template.jinja` и
`generation_config.json` целевой. После `cortiq convert` получается CMF,
который передаётся как `--tokenizer`. Ответы из кэша при этом
переимпортируются без новых запросов.

Рассуждающий 27B думает дольше 8k токенов на трёх задачах из четырёх.
Если сжатая модель будет работать без рассуждения, дешевле и полнее
`--no-think`. Если ответы массово упираются в лимит, команда в конце
предлагает поднять лимит или выключить рассуждение.

### Импорт существующего кэша ответов

```bash
cortiq teacher-data import train_combined.json OUT.tdata --tokenizer MODEL.cmf
```

Принимает массив `[prompt, rendered ChatML]` (кэш DTG-MA-ноутбуков) или
JSONL с `prompt`/`messages` и `response`. Токены считаются токенизатором
`--tokenizer`, то есть модели, которую будете сжимать. Повторы одного
промпта становятся сэмплами. Учтите: такие ответы написаны другой моделью,
поэтому годятся как текстовые цели, но не как распределение этой модели.

### Проверка

```bash
cortiq teacher-data inspect OUT.tdata --verify
```

## 2. Сжатие: подробности

```bash
cortiq compress SOURCE PROMPTS|DATA OUTPUT --ratio R [доп. параметры]
```

| Аргумент | Что это |
|---|---|
| `SOURCE` | `.cmf` (f16/bf16; q8 — с предупреждением), локальный HF-каталог или repo id |
| `PROMPTS` / `DATA` | `.jsonl` с промптами (модель ответит сама) или готовый `.tdata` |
| `OUTPUT` | итоговый `.cmf` в кодеке исходного |
| `--ratio` | доля размера исходной модели (параметров при том же кодеке) |
| `--ffn` / `--size` | альтернативы `--ratio`: доля нейронов FFN или целевое число параметров |

### Стадии

Каждая стадия запускается отдельным процессом и кэшируется в
`OUTPUT.work/` под ключом своих входов. Повторный запуск той же команды
продолжает с первой незавершённой стадии. Изменённый параметр
пересчитывает только свою стадию и следующие за ней.

| Стадия | Что делает |
|---|---|
| S0 prepare | исходник → рабочая f16-копия + q8_2f-копия для калибровки; проверка токенизатора данных |
| S1 illuminate | «засветка»: прогон исходной модели по ответам учителя (train и val раздельно), грамианы входа `down_proj` каждого слоя, энергия нейронов, кривые ошибки refit для любой ширины |
| S2 plan | ширина слоёв: одинаковая (`--allocate uniform`, по умолчанию), по кривым ошибки refit (`curve`) или по ним же с весом энергии выхода слоя (`abs`); крайние слои можно оставить полной ширины (`--protect-first N --protect-last M`, по умолчанию 0: защита сужает остальные слои сильнее и в сумме вредит — на 2B свёртка 0.330 против 0.320 без защиты), ширины кратны 128. На 0.8B равномерная раскладка дала NLL 0.621 против 0.629 у `curve` |
| S3 fold | сохраняемые нейроны по важности `‖W_down[:,j]‖²·⟨a_j²⟩`; выброшенные регрессируются на сохранённые, `W_down' = W_S + W_P·Πᵀ`, `Π = (Σ_SS+εI)⁻¹Σ_SP`; ридж и сам refit выбираются по val (`--refit auto`). Считается на GPU (см. ниже), если тренер доступен |
| S4 heal | KD-лечение против несжатого исходника на ответах учителя, лосс только на сгенерированных токенах, лучший чекпойнт по val. На NVIDIA (Vulkan, матричные блоки) и на Apple Silicon (Metal, simdgroup-матрицы 8×8) — на GPU ядрами `nvg-train`: веса хвостовых слоёв обучаются целиком (f32 + Adam, f16-плоскости обновляются каждый шаг), KL к top-64 исходника, слои ниже заморожены и обратный проход до них не идёт. Иначе — на CPU: `0.3·CE + 0.7·KL`, окна внутри записей, ворота генерации против зацикливания |
| S5 quant | только если задан `QUANT` (по умолчанию итог остаётся в кодеке исходника). `q4tp`/`q2tp`: GPTQ, калиброванный на тех же данных (окна внутри записей), k/v полного внимания в q8_2f (`--escort kv`); остальные кодеки — кодировщиком конвертера |
| S6 eval | на test: NLL ответов учителя, жадные продолжения test-промптов (зацикливание, длина относительно учителя, доля самостоятельных остановок), скорость, размер; ворота качества; `report.md` |

### Пресеты (`--recipe`)

| | `fast` | `balanced` (умолч.) | `full` | `quant-only` |
|---|---|---|---|---|
| засветка + свёртка | ✓ | ✓ | ✓ | — |
| лечение | — | FCD, 2 эпохи | FCD, 3 эпохи | — |
| GPTQ (только с `QUANT`), токенов калибровки | 32k | до 64k | до 64k | до 64k |

`quant-only` не трогает структуру: это GPTQ на данных задачи. Удобно как
опорная точка «что даёт структура против просто кванта».

### Полезные флаги

| Флаг | По умолчанию | |
|---|---|---|
| `--plan-only` | | показать план и остановиться |
| `--until S3`, `--from S4` | | остановиться после стадии / пересчитать начиная со стадии |
| `--heal-layers all\|deepN\|auto` | auto | какие слои лечатся (auto: все, если хватает памяти, иначе последние 5L/16) |
| `--heal-epochs`, `--heal-lr`, `--kd` | см. справа, 0.7 | эпохи: CPU 2 (`full` 3), GPU 6 (`full` 12); шаг: CPU 1e-5, GPU 1e-5 при хвосте до 30 % слоёв и ниже до 3e-6, когда учатся все (0.8B: все слои 1e-5 → 0.331, 5e-6 → 0.310, 3e-6 → 0.307); `--kd` — только CPU-путь |
| `--heal-device auto\|gpu\|cpu` | auto | где лечить: auto = GPU, если у карты есть кооперативные матрицы (NVIDIA Vulkan или Apple Metal), иначе CPU |
| `--heal-params ffn\|all`, `--heal-window`, `--heal-topk` | ffn, 2048, 64 | GPU-лечение: какие веса слоя учить (только MLP — 0.307 против 0.310 у всех весов на 0.8B при трети памяти), длина окна, сколько вероятностей учителя хранить на токен |
| `--loss-on answer\|generated\|all` | generated | на каких токенах лосс |
| `--keep-grams auto\|on\|off` | auto | хранить грамианы S1 на диске для свёртки (f32, 8·n² байт на слой — 155 ГБ у 27B); auto — если они занимают меньше половины свободного места. С ними несколько целей (`--size 20B`, `17B`, `14B` в разных `--work-dir` с общими S0/S1) сворачиваются из одной засветки, иначе S3 повторяет засветку |
| `--ridge` | 0.03,0.1,0.3 | сетка относительных риджей refit (на 1130 слоях 0.1 выигрывал в 86 % случаев, 0.003 — ни разу) |
| `--calib-tokens`, `--escort` | 65536, kv | калибровка GPTQ и тензоры в q8_2f |
| `--general-eval FILE` | | ppl на общем тексте в отчёте (контроль забывания) |
| `--compare MODEL.cmf` | | оценить ещё одну модель на тех же test-записях (другое сжатие, просто квант, другой учитель); можно повторять |
| `--select importance\|dtgma` | importance | как выбирать нейроны FFN: по засветке (один проход) или обученной маской DTG-MA (Патент 2, см. ниже) |
| `--write-on-fail` | | записать итог даже при проваленных воротах (`*.rejected.cmf`) |

### Выбор нейронов маской DTG-MA (`--select dtgma`)

Вместо ранжирования по засветке маска σ(m) на каждом нейроне FFN обучается
LM-лоссом задачи через всю модель под растущим L1-давлением. Каждые 25 шагов
на val проверяется жёсткая маска (σ > 0.5). Берётся первая контрольная
точка, где прорежено не меньше целевой доли. По обученным логитам выбираются
ширина каждого слоя (один общий порог) и сами нейроны. Свёртка с refit и
лечение дальше идут как обычно.

На NVIDIA маска живёт в GPU-тренере: гейт между SwiGLU и `down_proj`,
0.37 с на шаг, вся маска 0.8B за ~3 мин (через `skillbake` на хосте —
16.7 с на шаг, 70 мин). Давление растёт ×1.5 за оценку до цели; линейный
рост на 0.8B застревал на 15 %.

| Qwen3.5-0.8B | свёртка: засветка / DTG-MA | после лечения: засветка / DTG-MA |
|---|---|---|
| FFN 75 % | 0.364 / **0.339** | 0.281 / 0.282 |
| `--ratio 0.9` | 0.394 / **0.372** | 0.305 / 0.310 |
| Qwen3.5-2B, FFN 75 % | 0.320 / 0.320 | **0.255** / 0.261 |

На 0.8B маска даёт лучшую свёртку, после лечения результаты равны или
засветка чуть лучше (2B). Поэтому по умолчанию остаётся засветка: она
дешевле.

### GPU: NVIDIA и Apple Silicon

Засветка (S1), кривые refit (S1), маски DTG-MA (S2), свёртка (S3), лечение
(S4) и test NLL (S6) идут на GPU-тренере. На NVIDIA это Vulkan с тензорными блоками 16×16. На Mac —
Metal через wgpu с simdgroup-матрицами Apple 8×8. Рантайм на Mac при этом
остаётся на нативном Metal, тренер получает свой контекст. `CMF_TRAIN_GPU=0`
выключает тренер на Mac.

Шаг лечения Qwen3.5-0.8B (2 окна × 2048 токенов, все слои MLP) на M4:

| что включено | с/шаг |
|---|---|
| f32-запасные ядра внимания и GDN | 47 |
| + внимание на simdgroup-матрицах 8×8 | 27.6 |
| + быстрые ядра GDN на SIMD-группах | 17.4 |
| + тайл GEMM 64×64×32 (3.0 TFLOPS вместо 1.7) | 12.2 |

Для сравнения: RTX 5090 — 0.42 с/шаг. На MacBook шаг растёт до ~16 с, когда
машина нагревается. GEMM упирается в ~3 TFLOPS, это близко к практическому
пределу GPU M4, поэтому полное лечение 0.8B на нём занимает часы. Короткий
прогон: `--heal-epochs 1`.

**Свёртка на GPU.** Холецкий в f32 на эквилибрированной матрице (единичная
диагональ, как у GPTQ на устройстве: f32 видит корреляции, а не энергии
нейронов, у Qwen выбросы в ~10⁴ раз больше медианы), решение блочными GEMM.
Поправку `Aᵀ = (Σ_SS+εI)⁻¹·Σ_SP·W_Pᵀ` ищем для h правых частей, а не для p,
как у `Π`. Все ошибки считаются как следы со `Σ_SP·W_Pᵀ` и `Σ_SS·Aᵀ`.
Результат совпадает с хостовой версией в f64: на Qwen3.5-0.8B при 75 % FFN
у всех 24 слоёв те же ошибки val/train и тот же ридж. `CMF_FOLD_ON=host`
возвращает хост.

| один слой | хост (f64) | GPU, M4 |
|---|---|---|
| n 6144 → 4608, h 2048 (размер 2B) | 29 с | 2.2 с |
| n 17408 → 4352, h 5120 (27B, точка 14B) | ~11 мин (по масштабу) | 12 с |
| n 17408 → 10496 (27B, точка 20B) | — | 33 с |
| кривая refit n 17408 | — | 14 с |

S3 целиком на 0.8B: 21 с против 121 с на хосте.

**Засветка большой модели.** Грамианы, которые не помещаются рядом с
весами, набираются в несколько проходов. Каждый проход продолжает с
остаточного потока, на котором остановился предыдущий: он хранится на
хосте отдельно для train и для val. Поэтому каждый слой считается один
раз. Место под накопители берётся из того, что оставляют f16-веса и
рабочие буферы. У 27B на 96 ГБ это проходы примерно по 25 слоёв.

### Ворота качества (S6)

Итог сравнивается с исходной моделью на одних и тех же test-промптах:
зацикливаний не больше, чем у исходной, плюс одно; медианная длина ответа
не короче 0.7 от учительской; самостоятельных остановок не меньше, чем у
исходной, минус 10 % промптов. При провале итоговый файл не пишется
(код выхода 5), отчёт пишется всегда.

## Примеры (RTX 5090, лечение на GPU)

Данные: 483 промпта `calibration_prompts.jsonl`, учитель — сама модель
(для MoE — 80 кодовых промптов). Сплит 80/10/10. NLL считается на test, то
есть на ответах учителя, которых сжатие не видело. Генерация — 16
test-промптов. Итог в кодеке исходника (f16).

| модель | `--ratio` | параметры | test NLL: исходная → свёртка → лечение | ворота |
|---|---|---|---|---|
| Qwen3.5-0.8B | 0.9 | 0.773B → 0.697B | 0.189 → 0.394 → 0.305 | PASS |
| Qwen3.5-0.8B | 0.8 | 0.773B → 0.622B | 0.189 → 0.698 → 0.524 | FAIL: 3/16 зацикливаний |
| Qwen3.5-2B | 0.8 | 1.943B → 1.565B | 0.185 → 0.464 → 0.354 | PASS |
| LFM2.5-8B-A1B (MoE) | 0.9 / 0.8 / 0.65 | 8.47B → 7.62 / 6.77 / 5.49B | 0.280 → 0.289 / 0.332 / 0.399 (без лечения) | — |

- У 0.8B треть параметров — эмбеддинги, которые не сжимаются. Поэтому
  `--ratio 0.8` снимает с FFN 30 % ширины, и это уже слишком.
- Время одного прогона 0.8B на 5090: около 6 минут без генерации данных.
  Засветка 36 с, свёртка ~1 мин, лечение ~1.5 мин, оценка ~2 мин.
- Для сравнения на 2B: одно квантование q4tp даёт 1.03 ГБ и NLL 0.225.
  Сжатие под задачу не заменяет квантование, а добавляется к нему.

## 3. Использование данных учителя в других командах

`.tdata` принимается как калибровочный корпус: `PATH.tdata[:train|val|test|all][=SHARE]`.

```bash
cortiq quantize-gptq model-f16.cmf --codec q4tp --calib-model model-q8_2f.cmf \
    --calib task.tdata:train=0.8 --calib wiki.txt=0.2 --tokens 65536 --output model-q4tp.cmf
```

Окна строятся внутри записей и никогда не склеивают два промпта.
