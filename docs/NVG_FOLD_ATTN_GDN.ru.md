# Структурная свёртка 27B → «9B»: математика внимания и GDN

Что уже есть в ноутбуках и прототипах: свёртка **FFN** в замкнутой форме —
keep-set S по измеренной важности и локальной непрерывности, выброшенные
нейроны P регрессируются на оставшиеся:

    Π = Σ_SS⁻¹ Σ_SP,     W_down' = W_down[:,S] + W_down[:,P]·Π,
    gate/up' = строки S (с пересчётом дисперсии).

Σ — грамиан ВХОДА down_proj (активаций после SiLU·up) на калибровочных
токенах; «весовой» аналитический Σ = (WgWgᵀ)⊙(WuWuᵀ)⊙(P⊗P) измерен хуже
активационного. Внимание и GDN там **не трогаются**: только дообучаются
в Genesis/FCD. Предыдущие прототипы для голов внимания проверены на
SmolLM2-135M; вариант для GDN ещё не был готов.

Ниже — та же математика, доведённая до обоих типов слоёв Qwen3.5/3.8,
и честная граница того, что она даёт без обучения.

## 1. Единица свёртки — голова, читающая линейка — o_proj / out_proj

Обе конструкции устроены одинаково: нелинейный блок выдаёт набор голов
`a = concat_h a_h`, а слой заканчивается ЛИНЕЙНОЙ проекцией `y = W·a`.
Всё, что делает свёртка, — переносит линейно предсказуемую часть
выброшенных голов в проекцию оставшихся. Голова остаётся нетронутой
внутри (softmax, рекуррентность GDN — что угодно), меняются только
строки/столбцы линейных карт вокруг неё. Поэтому это ЗАМКНУТАЯ ФОРМА и
не требует ни градиентов, ни GPU: один проход калибровки за
активациями и одно решение СЛАУ на слой.

Точность: если `a_P ∈ span(a_S)` линейно — свёртка точна. Ошибка =
остаток регрессии `‖a_P − Πᵀa_S‖²/‖a_P‖²` (R/S в терминах ноутбуков),
его надо печатать на каждом слое: это единственная честная метрика
«сколько потеряли до heal».

## 2. Полное внимание (16 слоёв; 24 q-голов / 4 kv-головы, hd = 256)

Вход o_proj: `a ∈ R^{24·256}`, `a_h = gate_h ⊙ softmax(q_h Kᵀ_{g(h)}) V_{g(h)}`
(в Qwen3.5 attention output-gate сидит в q_proj: на голову 256 q +
256 gate). kv-головы (4) не трогаем — иначе ломается GQA. Единица —
q-голова. В каждой kv-группе (6 голов) оставить 4 → 16 голов: ровно
конфиг Qwen3.5-9B.

    E_h = ⟨‖a_h‖²⟩ по калибровке (o_proj input, УЖЕ с гейтом)
    imp_h = ‖W_o[:,h]‖²_F · E_h  (+ continuity: 0.5·|Δlog| по соседним головам группы)
    S = top-4 в каждой группе (или порог ρ_c внутри группы)
    Σ = ⟨a aᵀ⟩ ∈ R^{6144×6144};  Π = Σ_SS⁻¹ Σ_SP  (ридж εI, ε ~ 1e-3·tr/n)
    W_o' = W_o[:,S] + W_o[:,P]·Π                       (H × 4096)
    W_q' = строки {q_h, gate_h : h ∈ S}                (4096·2 × H)
    q_norm, k_norm, W_k, W_v — без изменений (нормы общие на все головы)

Дисперсионный пересчёт как в FFN-свёртке: `W_o' *= sqrt(var(W_o)/var(W_o'))`
по столбцам? — НЕТ: для o_proj пересчёт не нужен и вреден (Π уже даёт
несмещённую оценку в L2); он был нужен для gate/up, чей масштаб
статистически «худеет» при обрезке.

## 3. GDN (48 слоёв; nk = 16 key-голов, nv = 48 value-голов, GVA 3:1, dk = dv = 128)

Слой: `x → in_proj_qkvz → [q(16·128) | k(16·128) | v(48·128) | z(48·128)]`,
`x → in_proj_ba → [b(48) | a(48)]`, conv1d (depthwise, k = 4) по q,k,v;
`A_log(48)`, `dt_bias(48)`; рекуррентность на value-голову h с ключом её
группы g(h): `S_h ← α_h S_h + β_h k_g (v_h − S_hᵀ k_g)ᵀ`, `o_h = S_hᵀ q_g`;
gated RMSNorm `ũ_h = norm(o_h)⊙silu(z_h)` (вес нормы — на канал, 48·128);
`y = W_out · concat_h ũ_h`.

Единица — value-голова (ключевые головы все остаются: они делят
рекуррентность с тремя value-головами, их выброс не замкнут). Оставить
2 из 3 в каждой ключевой группе → nv 32 при nk 16: снова ровно GDN
конфиг Qwen3.5-9B.

    u = concat_h ũ_h — вход out_proj;  E_h = ⟨‖ũ_h‖²⟩;  imp_h = ‖W_out[:,h]‖²·E_h (+continuity)
    S: 2 из 3 в каждой k-группе;  Σ = ⟨u uᵀ⟩ (6144×6144);  Π = Σ_SS⁻¹ Σ_SP
    W_out' = W_out[:,S] + W_out[:,P]·Π                  (H × 4096)
    in_proj_qkvz' = q,k как были; строки v_h, z_h только для h ∈ S
    in_proj_ba'   = строки b_h, a_h для h ∈ S
    conv1d'       = каналы q,k как были + каналы v_h, h ∈ S   (порядок каналов [q|k|v])
    A_log', dt_bias' = элементы S;  norm' = веса каналов S

Почему это та же формула, что и для внимания: рекуррентность каждой
оставшейся головы не зависит от выброшенных (связь только через общий
ключ, а ключи остаются), поэтому `ũ_S` после свёртки — ровно те же
числа, что до неё; меняется только линейное считывание. То есть
GDN-свёртка по value-головам ТОЧНО так же замкнута, как FFN — и
именно она стояла «недоделанной».

## 4. Чего замкнутая форма НЕ даёт: глубина и скрытая размерность

Скелет Qwen3.5-9B — это H = 4096, L = 32 (8 attention), FFN 12288,
heads 16/4, nv 32/nk 16. Пункты 2–3 + FFN-свёртка дают **поголовно
9B-конфиг в каждом слое**, но при H = 5120 и L = 64:

    FFN  3·5120·12288·64 = 12.1B
    GDN  (5120·(16·128·2 + 32·128·2) + 4096·5120)·48 = 4.0B
    attn (5120·(16+8)·256 + 4096·5120)·16 = 0.84B
    embed + lm_head 2·248320·5120 = 2.5B          → ≈ 19.5B (q4tp ≈ 10.5 ГБ)

Дальше вниз (к настоящим 9B) нужны две операции, у которых замкнутой
формы нет:

- **Глубина 64 → 32.** Слой — нелинейное отображение; «сплавить» два
  слоя в один линейной алгеброй нельзя. Что можно без обучения: выброс
  слоёв по энергии с сохранением рисунка [G,G,G,A] и rank-k перенос
  линейных карт выброшенного слоя в соседа (`colab_emergent_gguf`,
  ни разу не запускался). Ошибка — не остаток регрессии, а изменение
  функции; её лечит только heal.
- **H 5120 → 4096.** Резидуальный поток 27B и 9B живут в разных
  базисах. Линейную карту P (4096×5120) можно подобрать риджем по
  активациям ДВУХ моделей на одних токенах (`h9 ≈ P·h27`), и переливать
  каждую линейку `W' = P·W·Q⁺` — но между линейками стоят RMSNorm,
  SiLU, softmax, gated-norm, и композиция через них точной не бывает.
  Это первое приближение для инициализации KD, не готовая модель.
  (Именно об этом было «HFT v2.1 ОТКЛЮЧЕН: OLS без attention пропускает
  вклад attention» в `colab_v2` — тот же эффект.)

Итого честно: **«перелить 27B в чистую 9B без больших мощностей» — это
свёртка до 19.5B (замкнуто, часы CPU) + heal**; настоящий 9B-скелет
требует дистилляции от 27B (сотни миллионов токенов; на одной 5090
это дни, не часы). Сама Qwen3.5-9B при этом уже существует как
«общая» модель — переливать в неё есть смысл только KD-обучением, где
27B — учитель, а не источник весов.

## 5. Эксперимент, который запускается сейчас (под, CPU-часть)

1. bf16 Qwen3.8-27B → RAM (18 шардов потоково), transformers на CPU.
2. Калибровка ~30k токенов общего состава (wikitext-2 train + код +
   диалог); хуки: входы `down_proj`, `o_proj`, `linear_attn.out_proj`
   → грамианы Σ (FFN 17408², attn 6144², GDN 6144²) f64.
3. Свёртка по §1–3 + FFN 17408 → 12288 (keep-set по важности и локальной
   непрерывности, Π-регрессия). Печать остатка регрессии на слой.
4. Экспорт safetensors + config (intermediate 12288, heads 16, nv 32),
   `cortiq convert --quant q4tp`, ppl wikitext-2 против 8.79 у 27B,
   аквариум тем же промптом/сидом.
5. Heal — отдельно и на GPU: LoRA-KD от 27B на калибровочном миксе.
