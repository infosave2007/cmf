# MiniMax-H3-Image

*Языки: [English](MINIMAX_H3_IMAGE.md) · **Русский** · [中文](MINIMAX_H3_IMAGE.zh.md)*

[MiniMax-H3-Image](https://huggingface.co/MiniMaxAI/MiniMax-H3-Image) генерирует и редактирует изображения от 4
до 16 мегапикселей за шесть шагов. cortiq запускает её из одного файла CMF на 24.6 ГБ: в нём диффузионный
трансформер (20 млрд параметров в 4 битах), энкодер промпта Qwen3-VL с башней зрения (4 бита) и VAE (8 бит).
На карте NVIDIA весь конвейер идёт через собственный бэкенд CUDA, на остальных GPU через Vulkan или Metal.
Потолок памяти карты позволяет запускать модель на маленькой карте.

```bash
cargo install --git https://github.com/infosave2007/cmf --branch h3-image cortiq-cli --features cuda
# текст в картинку
CMF_GPU=cuda cortiq imagine minimax-h3-image-q4tp.cmf --prompt @prompt.txt --out out.png
# правка: <Picture 1> в промпте — файл из --image
CMF_GPU=cuda cortiq imagine minimax-h3-image-q4tp.cmf --image photo.png --prompt @edit.txt --out edit.png
# карта с 6 ГБ
CMF_GPU=cuda CMF_GPU_VRAM_MB=6000 cortiq imagine minimax-h3-image-q4tp.cmf --prompt @prompt.txt --out out.png
# Vulkan (любой производитель) и Metal: бэкенд по умолчанию
cortiq imagine minimax-h3-image-q4tp.cmf --prompt @prompt.txt --out out.png
```

Файл лежит на Hugging Face: [infosave/MiniMax-H3-Image-cmf](https://huggingface.co/infosave/MiniMax-H3-Image-cmf). Модель распространяется по лицензии
MiniMax-H3-Image Community License, которая ограничивает территории использования; подробности на странице.

## Текст в картинку

| опция | что делает |
|---|---|
| `--prompt TEXT` или `--prompt @FILE` | описание; длинное удобнее держать в файле |
| `--width`, `--height` | кратны 32, по умолчанию 2048 x 2048 |
| `--min-area PIXELS` | наименьший холст, на котором запускается модель, по умолчанию 4194304 (2048 x 2048); меньший размер генерируется на таком холсте с тем же соотношением сторон и уменьшается, как делает эталонный сервер. `--min-area 1024` это отключает |
| `--seed N` | по умолчанию 42; `--num-images K` рисует сиды N .. N + K - 1 с одним кодированием промпта |
| `--steps N` | меньше шести шагов модели: та же сетка сигм более длинными шагами |
| `--out FILE` | PNG, JPEG или PPM по расширению |

Модель дистиллирована: шесть шагов на собственной сетке сигм, без classifier-free guidance и без негативного
промпта. Рабочий диапазон от 4 мегапикселей (2048 x 2048) до 20, лучший результат около 16 (4096 x 4096).
Модель ждёт подробное английское описание всей картинки. Авторы получают его из короткого запроса
расширителем промпта (API H3-Image-Context-IR или локальная модель MiniMax-H3-Image-PE). В cortiq расширителя
нет: описание нужно написать самому или развернуть любой языковой моделью.

## Правка изображений

`--image FILE` превращает запуск в правку; опцию можно повторять. В промпте картинки называются
`<Picture 1>`, `<Picture 2>` и так далее в порядке передачи, `<Picture 1>` — редактируемая. Без `--width` и
`--height` результат получает размер первой картинки, приведённый к короткой стороне от 1024 до 2048 пикселей.

Энкодер промпта видит каждую картинку через башню зрения Qwen3-VL при короткой стороне 1024 пикселя, а
трансформер дополнительно получает её латент VAE строками последовательности перед целевой картинкой. Правка
одной картинки 1024 x 1024 на холсте 2048 x 2048 идёт по 4096 целевым строкам, 1024 опорным и промпту.

Собственные промпты модели для правки — это задания, где назван каждый объект и сказано, что сохраняется
(`The man on the left in <Picture 1> is <Subject 1>. ... The target image shows ...`). Короткая инструкция
тоже работает, но сохраняет меньше: надписи, не названные в промпте, обычно меняются.

## Маленькие карты

`CMF_GPU_VRAM_MB` — потолок того, что процесс держит на карте. Блоки трансформера, которые под него не
помещаются, на карте не хранятся: их веса проходят через карту каждый шаг. То, что растёт с размером картинки,
невелико: панели считаются порциями строк, а внимание не хранит матрицу оценок.

2048 x 2048, CUDA, NVIDIA RTX 2000 Ada, 16 GB:

| потолок | всего, с | шаг, с | пик памяти карты, МиБ |
|---|---:|---:|---:|
| нет | 50,3 | 7,38 | 12 654 |
| `CMF_GPU_VRAM_MB=8000` | 53,5 | 8,05 | 7 634 |
| `CMF_GPU_VRAM_MB=6000` | 54,4 | 8,18 | 5 720 |
| `CMF_GPU_VRAM_MB=4000` | 60,2 | 9,15 | 3 710 |

Под потолком 4 ГБ получается та же картинка: PSNR 49,6 дБ к прогону без потолка.

## Как это устроено на CUDA

- **Трансформер — одна цепочка на карте.** Поток остатка уходит на карту один раз за шаг и один раз
  возвращается. Каждый блок целиком считается там: RMS-норма с модуляцией adaLN в f16, произведение qkv, норма
  q/k по головам и поворот, внимание, выходная проекция, остаток с гейтом, затем SwiGLU MLP. Произведения
  считает cuBLAS на тензорных ядрах (операнды f16, суммы f32).
- **Внимание ничего не материализует.** Варп ведёт 16 строк запроса одной головы и проходит ключи по 16: два
  произведения на тензорных ядрах (`mma.sync`) и softmax между ними в регистрах. Ключи и значения лежат в том
  порядке, в котором их читают дорожки. Замер с выключением частей ядра показал, что время уходило на загрузку
  операндов, а не на произведения; перекладка сократила его вдвое.
- **Веса остаются в своём кодеке.** Блок q4tp занимает на карте 222 МБ и становится плотной плоскостью f16
  только на время своего произведения; один буфер плоскостей обслуживает весь стек.
- **Энкодер промпта** (50 слоёв Qwen3-VL-32B) идёт так же, с причинным ядром внимания. Каждый вес нужен один
  раз, поэтому не хранится: энкодер держит плоскости не больше одного слоя.
- **VAE** декодирует тайлы по 256 пикселей пачками через ту же цепочку; опорные картинки правки кодирует
  цепочка свёрток (панели im2col и одно произведение на свёртку).

На Vulkan и Metal конвейер использует пооперационные ядра видеопути MiniMax-H3: активации каждого блока
ходят на хост и обратно.

## Упаковка

```bash
cortiq animate-pack --out minimax-h3-image-q4tp.cmf \
  --in mmh3-turbo-fl2va-q4tp.cmf \
  --dit minimax_h3_image_pruned_bf16.safetensors \
  --image-vae minimax_h3_image_vae_fp16.safetensors --image-vae-quant q8_2f \
  --drop avae --quant q4tp
```

`--dit` — «pruned» чекпойнт ComfyUI (`Comfy-Org/MiniMax-H3-Image`): adaLN в нём уже свёрнут в кривую ранга 8,
а выходной слой — банк из шести голов по шагам. Энкодер промпта тот же, что у MiniMax-H3, поэтому `--in`
переносит его и башню зрения из контейнера MiniMax-H3; `--te` упаковывает его из исходника bf16.

## Что проверено

- Цепочка против пооперационного пути (каждое произведение — отдельный GEMM в f32) на правке 2048 x 2048:
  PSNR между картинками 54,0 дБ.
- CUDA против Vulkan, 1024 x 1024, тот же сид: 44,6 дБ.
- Потолок 4 ГБ против прогона без потолка: 49,6 дБ.
- Цепочка декодера VAE против пооперационного пути: 47,5 дБ; против весов f16: 48,5 дБ.
- `CMF_H3_SAT=1` считает значения f16, упёршиеся в насыщение: на генерации и правке их нет.
- 8-битный энкодер промпта под тем же трансформером: состояния отличаются на 3 % (относительное RMS),
  картинки на 17,7–25,4 дБ, уровень детали тот же. В файле оставлены 4 бита.
- Не проверено: эталонная реализация на той же карте не запускалась, поэтому попиксельного сравнения с ней нет.

## Переключатели

| переменная | действие |
|---|---|
| `CMF_GPU=cuda` | собственный бэкенд CUDA (сборка с `--features cuda`) |
| `CMF_GPU_VRAM_MB=N` | потолок памяти карты |
| `CMF_CUDA_PROF=1` | времена стадий цепочек (синхронно, медленнее) |
| `CMF_H3_SAT=1` | счётчик насыщенных значений f16 и наибольших величин в панелях цепочки |
| `CMF_MMH3_CHAIN=0`, `CMF_TE_CHAIN=0`, `CMF_VAE3D_CHAIN=0` | пооперационный путь для трансформера, энкодера, VAE |
| `CMF_H3_FLASH=0` | внимание двумя пакетными произведениями на порцию вместо flash-ядра |
| `CMF_LATENT_OUT=FILE`, `CMF_INIT_LATENT=FILE` | записать итоговый латент; начать с заданного шума |
| `CMF_TE_DUMP=FILE`, `CMF_TE_LOAD=FILE`, `CMF_TE_FROM=FILE.cmf` | записать состояния промпта; взять состояния другого прогона; взять энкодер из другого контейнера |

## Ограничения

- **Правка плотно детализированной контрастной картинки на холсте 2048 x 2048 выходит пережжённой**
  (перенасыщенной, с постеризацией). Та же правка на 1024 x 1024
  (`--width 1024 --height 1024 --min-area 1024`) чистая, как и правки более мягких картинок на 2048 x 2048.
  8-битный энкодер, 8-битный трансформер и пооперационный путь в f32 дают тот же результат: кодек и цепочка
  исключены, причина не найдена.
- Vulkan работает пооперационно и в 4,7 раза медленнее CUDA на той же карте. Metal использует те же
  ядра и не измерялся.
- Ядру внимания нужны тензорные ядра с `mma.sync` (compute capability 8.0 и выше); на более старых картах
  внимание считается двумя пакетными произведениями.
- Дальнее поле (O(1)) турбо-файлов языковых моделей здесь неприменимо: оценка на собственных операндах модели
  при 2048 x 2048 даёт изменение выхода внимания на 12–65 %.
