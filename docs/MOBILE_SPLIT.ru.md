# Телефон в сетевом сплите: что добавить в приложение

Статус: ABI готов и измерен в 0.5.70. Работа на стороне приложения — не начата.
Связанные документы: `MULTI_DEVICE_ROADMAP.ru.md` (§3.5, Phase 4b),
`CMF_V2_SPEC.md`, заголовок `crates/cortiq-ffi/include/cortiq.h`.

---

## 0. Что именно измерено — и почему роль важнее сплита

Стенд: Xiaomi 12 Lite (SD778G, 4×A78 2.4 ГГц + 4×A55, 7.3 ГБ RAM, из них
свободно ~2) на USB-C и на одном Wi-Fi 5 ГГц 802.11ax с MacBook M4 24 ГБ.
Реальный `cortiq worker` в обе стороны, не эмуляция.

**Сплит слоёв не ускоряет токен.** Токен идёт по слоям последовательно;
распределение даёт память, а не параллелизм. Замерено в обе стороны и на обоих
транспортах: любая конфигурация, где считают обе стороны, медленнее, чем
быстрейшая сторона в одиночку. Bonsai 1.7B: Mac 28.6 tok/s, телефон 14.3
(steady), пополам по USB — 14.0.

Отсюда следуют **четыре роли**, и приложение должно выбирать роль, а не «процент
нагрузки»:

| роль | что даёт | измерено |
|---|---|---|
| **Тонкий клиент** — десктоп держит всё, телефон только рисует | модель, которой на телефоне быть не может | 34.7B MoE на телефоне с 2 ГБ свободных: **16.3 tok/s** |
| **Офлоад префилла** — длинный промпт считает десктоп | время до первого токена | 1800 позиций: 86.9 с → **11.3 с (7.7×)** |
| **Расширитель памяти** — телефон держит хвост слоёв десктопа | модель больше десктопа | выигрыш только когда модель не влезает; иначе чистый минус |
| **Реплика** — телефон обслуживает запрос целиком | пропускная способность | это сегодняшний экран «Сервер», он уже верный |

Транспорт ранжируется по **хвосту**, а не по мегабитам. Круг 4 КБ (ровно один
hidden при hidden 2048):

| путь | p50 | p90 | p99 |
|---|---|---|---|
| USB | **1.89 мс** | 2.19 | 2.94 |
| Wi-Fi 5 ГГц ax, −53 dBm, линк 680 Мбит/с | 8.95 | 11.39 | **94.81** |
| Wi-Fi с паузой 100 мс между токенами | 9.56 | **85.14** | 189.8 |

Один круг на токен означает, что p99 видит пользователь. Кабель выигрывает у
отличного Wi-Fi впятеро по медиане и в тридцать раз по хвосту.

## 1. Что появилось в ABI (0.5.70)

Три функции, все аддитивные. Приложение, которое их не зовёт, работает как
раньше.

```c
int32_t     cortiq_worker_start(const char *config_json);
int32_t     cortiq_set_peer(const char *config_json);
const char *cortiq_peer_stats(void);
```

**`cortiq_worker_start`** — `cortiq worker` как вызов: телефон отдаёт диапазон
слоёв своей копии модели чужому координатору. Слушатель живёт на фоновом потоке.

```json
{"model": "/data/.../model.cmf", "listen": "0.0.0.0:9911", "token": "secret"}
```

Порт биндится и файл проверяется **на потоке вызывающего**, поэтому занятый порт
или отсутствующий файл — это `-1` и текст в `cortiq_last_error()`, который можно
показать, а не молча мёртвый поток. Токен **обязателен** для любого адреса, кроме
loopback: без него воркер откажется слушать.

**`cortiq_set_peer`** — наоборот: каждая последующая генерация идёт через пира,
который держит **тот же** файл.

```json
{"addr": "192.168.1.5:9911", "token": "secret",
 "split": 0, "dtype": "f16", "head": true}
```

- `split` — первый слой, который считает пир. `0` = все, и тогда эта сторона
  держит только токенизатор. По умолчанию половина стека.
- `head` — пир владеет ещё и `lm_head` с сэмплером и отвечает **id токена**.
- `dtype` — `f32` повторяет локальный текст побайтно, `f16` вдвое режет провод и
  законно меняет текст.

`null` или `{}` очищает и возвращает локальный режим. Соединение поднимается
лениво, на первой генерации, — недоступный пир падает там, с сообщением.

**`cortiq_peer_stats`** — чего пир стоит **сейчас**, JSON:

```json
{"thermal_mc":34300,"powered":null,"cpu_khz_cur":691200,
 "cpu_khz_max":2400000,"mem_avail_kb":1467000,"threads":4,
 "platform":"android/aarch64"}
```

`null` означает «платформа не отдаёт», а не ноль. Не подставляйте туда нули:
планировщик, прочитавший 0 МГц, припаркует живой узел.

## 2. Флаг `head` — самое дешёвое ускорение, какое здесь есть

Голова (`final norm` + `lm_head` + сэмплер) **не уменьшается**, сколько слоёв ни
унеси. На телефоне она стоила 29 мс из 73 мс токена — то есть телефон-клиент был
упёрт в собственную голову независимо от скорости десктопа. С `head: true`
голова уезжает к пиру, и обратно едет id токена.

Телефон-координатор + Mac-воркер, все слои у Mac, по USB:

| модель | `head: false` | `head: true` | |
|---|---|---|---|
| bonsai 1.7B | 12.6–13.0 tok/s | **26.0–27.3** | 2.06× |
| Qwen3.6 35B-A3B q2tp (34.7B) | 9.1–9.4 | **15.7–16.3** | 1.72× |

В этом режиме провод на токен — **16 байт** (12 туда, 4 обратно) вместо 4 КБ, а
строка `net:` показывает «99% of decode wall»: телефон только ждёт и
детокенизирует.

Почему нельзя было унести **только** голову, без сэмплера: логиты этих моделей —
151 669 чисел, 300 КБ на токен в f16. По измеренной полосе Wi-Fi 14.6 МБ/с это
20 мс на токен — дороже, чем экономит. Ехать должен id.

**Парити:** при одинаковом сплите и одинаковом бэкенде сторон `head: true` даёт
побайтно тот же текст, что и `head: false`, — и в greedy, и в сэмплинге с
фиксированным seed (конфиг сэмплера едет к пиру в Assign; иначе дефолтная
температура на той стороне молча переписала бы ответ). Оговорка: режим переносит
голову на **устройство пира**, поэтому если стороны на разных бэкендах
(телефон CPU, десктоп Metal), текст может законно измениться — то же правило, что
для любого кросс-девайс сплита.

## 3. Что сделать в приложении, по шагам

### Шаг 1. Пересобрать нативную библиотеку

Матрица сборки НЕ одинаковая по ABI, и обе особенности молча ломают
приложение, если их пропустить.

```sh
# 64-битные ABI — с фичей gpu. Она НЕ дефолтная: сборка без неё даёт
# библиотеку вдвое меньше и приложение без Vulkan, без единой ошибки.
cargo ndk -t arm64-v8a -t x86_64 --platform 26 \
  build --release -p cortiq-ffi --features gpu

# armeabi-v7a — без gpu (так собрано то, что лежит в приложении) И с
# 16 KB-страницами: по умолчанию линкер даёт выравнивание 0x1000, а такая
# библиотека не загрузится на Android 15 и не пройдёт в Play.
RUSTFLAGS="-C link-arg=-Wl,-z,max-page-size=16384" \
  cargo ndk -t armeabi-v7a --platform 26 build --release -p cortiq-ffi

# iOS — тоже с gpu, и обе цели: устройство и симулятор (arm64)
cargo build --release -p cortiq-ffi --target aarch64-apple-ios --features gpu
cargo build --release -p cortiq-ffi --target aarch64-apple-ios-sim --features gpu
```

Проверить ПЕРЕД копированием — три символа на месте и выравнивание 0x4000
у всех трёх ABI (`NDK/toolchains/llvm/prebuilt/*/bin`):

```sh
llvm-nm -D libcortiq_ffi.so | grep -c "cortiq_\(worker_start\|set_peer\|peer_stats\)"   # 3
llvm-readelf -l libcortiq_ffi.so | awk '/LOAD/{print $NF}' | sort -u        # 0x4000
```

Размеры — тоже проверка: arm64 ≈ 14.1 МБ и x86_64 ≈ 14.5 МБ (с gpu),
v7a ≈ 4.5 МБ (без), обе iOS-библиотеки ≈ 88.7 МБ (с gpu; без неё 53.6 —
если получилось столько, фича потерялась).

**Символы в iOS-архиве обычным `nm` не видны, и это не поломка.** Профиль
релиза собирает с `lto = "thin"`, поэтому члены архива — это LLVM-битkod, и
`nm` возвращает пусто даже для `_cortiq_version`. Проверять надо линковкой:

```sh
printf 'int32_t cortiq_set_peer(const char*);\nint main(){return cortiq_set_peer("{}");}\n' > probe.c
xcrun -sdk iphoneos clang -target arm64-apple-ios13.0 probe.c libcortiq_ffi.a \
  -framework Metal -framework Foundation -framework CoreFoundation \
  -framework CoreGraphics -framework QuartzCore -framework IOSurface -o probe
```

`CoreGraphics` в этом списке обязателен: Metal-поверхность wgpu тянет
`CGColorSpace*`, и без него линковка падает на них, а не на наших символах.

Скопировать `libcortiq_ffi.so` в `android/app/src/main/jniLibs/<abi>/` и
обновить `native/cortiq_ffi.h` из `crates/cortiq-ffi/include/cortiq.h`.

**Обе стороны обязаны быть на одной версии протокола.** Рукопожатие сверяет
`WIRE_VERSION` (сейчас 5) и отказывает с текстом «wire version N ≠ 5 — upgrade
one side». Это фича: несовместимость видна сразу, а не как мусор в выводе.

### Шаг 2. Биндинги

В стиле существующего `lib/data/services/inference/native_engine.dart`:

```dart
typedef _WorkerStartNative = ffi.Int32 Function(ffi.Pointer<Utf8>);
typedef _WorkerStartDart = int Function(ffi.Pointer<Utf8>);
typedef _SetPeerNative = ffi.Int32 Function(ffi.Pointer<Utf8>);
typedef _SetPeerDart = int Function(ffi.Pointer<Utf8>);
typedef _PeerStatsNative = ffi.Pointer<Utf8> Function();

late final _workerStart = _lib
    .lookupFunction<_WorkerStartNative, _WorkerStartDart>('cortiq_worker_start');
late final _setPeer =
    _lib.lookupFunction<_SetPeerNative, _SetPeerDart>('cortiq_set_peer');
late final _peerStats =
    _lib.lookupFunction<_PeerStatsNative, _PeerStatsNative>('cortiq_peer_stats');

/// Гонит последующие генерации через десктоп. `split: 0` + `head: true` —
/// режим тонкого клиента: телефон только токенизирует.
bool useDesktop(String addr, String token,
    {int split = 0, bool head = true, String dtype = 'f16'}) {
  final cfg = jsonEncode({
    'addr': addr, 'token': token, 'split': split,
    'head': head, 'dtype': dtype,
  }).toNativeUtf8();
  try {
    return _setPeer(cfg) == 0;
  } finally {
    calloc.free(cfg);
  }
}

/// Вернуться к локальной модели.
void useLocal() => _setPeer(ffi.nullptr);

Map<String, dynamic> peerStats() =>
    jsonDecode(_peerStats().toDartString()) as Map<String, dynamic>;
```

`cortiq_set_peer` не блокирует и не ходит в сеть — соединение поднимется на
первой генерации. Ошибку показывать оттуда же, откуда сейчас показываются ошибки
генерации: через `cortiq_last_error()`.

### Шаг 3. Экран «Компаньон»

Минимум, который уже полезен:

1. Поле адреса и токена (или QR — на экране «Сервер» QR уже рисуется, здесь
   нужен обратный: десктоп показывает, телефон сканирует).
2. Переключатель роли: **«Считать здесь»** / **«Считать на десктопе»**.
3. Строка состояния, честная и по делу — что где считается и по какому проводу.
4. Кнопка «Проверить» — один короткий запрос; если пир не поднят, показать текст
   ошибки, а не крутилку.

Требование к модели: **на обеих сторонах должен лежать один и тот же `.cmf`**.
Идентичность проверяется по `dir_hash` при рукопожатии, чужой файл отвергается —
химера не собирается никогда. В UI это значит: список моделей десктопа нужно
сверять с локальным списком, а не предлагать «подключиться к чему угодно».

Файл нужен на телефоне даже при `split: 0` — из него читаются токенизатор и
шаблон чата. На диске это полный размер модели, в памяти — только тронутые
страницы (34.7B q2tp: 12.9 ГБ на диске, работает при 2 ГБ свободной RAM).

### Шаг 4. Роль воркера — только на переднем плане

`cortiq_worker_start` поднимает слушателя, но телефон обязан оставаться живым и
не уходить в дозу: сервис переднего плана + wake lock. В приложении уже есть
`core/util/foreground_task.dart` и `core/util/keep_awake.dart` — тот же путь, что
у режима «Сервер».

### Шаг 5. Опрос состояния

Дёргать `cortiq_peer_stats()` между ходами (не в цикле декода) и показывать
`cpu_khz_cur / cpu_khz_max`. Ниже ~50% на активном декоде означает, что
губернатор той стороны не проснулся, — и это чинится, см. ловушку 3.

## 4. Ловушки — каждая стоила замера

**1. Wi-Fi лечится только батчем.** Медиана 9 мс терпима, хвост 95 мс — нет; при
паузах между токенами p90 уползает на 85 мс. Один круг на токен означает, что
хвост попадает в глаза пользователю. Пока нет спекулятивного батча (см. §5),
**для Wi-Fi честный дефолт — не сплит, а локальная модель**; кабель включать
автоматически, когда он есть.

**2. Сплит влезающей модели — минус, а не плюс.** Не предлагайте «ускорить
локальную модель телефона десктопом»: измерено, что это медленнее. Предлагайте
«запустить модель, которой здесь нет».

**3. Губернатор телефона стоит вдвое.** На той же железке при 36 °C, без всякого
троттлинга, один и тот же воркер отдавал свой диапазон то за 22.6 мс, то за
42.4 мс: `schedutil` не разгоняет большие ядра под задачу, которая считает
несколько миллисекунд и блокируется на сокете (замерено: cpu4 держался на 691 из
2400 МГц). Что делать, по убыванию законности:

- **ADPF `PerformanceHintManager`** (Android 12+): `APerformanceHint_createSession(tids,
  target_ns)` и `reportActualWorkDuration` на токен. Именно этим игровые движки
  объясняют ядру дедлайн кадра. В ABI **уже есть `cortiq_worker_tids()`** — то,
  что нужно на вход.
- Сервис переднего плана: процесс попадает в cpuset `top-app` и получает
  прайм-ядро. Все числа выше сняты с `adb shell`, то есть **нижняя граница**;
  внутри приложения должно быть лучше.
- `CMF_NET_SPIN` (мкс, по умолчанию 3000) — ограниченный спин вместо
  блокирующего чтения, дал +9%. Полный спиннер на больших ядрах давал +80%, но
  это батарея; как режим не годится.

**4. Не трогайте число потоков.** Пул сам размеряется по большим ядрам
(`cores_from_capacities`), и это уже оптимум: пиннинг на большой кластер даёт
+0.3% (шум), а отпустить пул на все 8 ядер — **−28%** (14.3 → 10.3 tok/s), потому
что ядро A55 становится стрегглером на каждом барьере слоя. `cortiq_set_threads`
здесь — способ сделать хуже.

**5. `f16` меняет текст.** Провод вдвое дешевле, расхождение с локальным выводом
наступает примерно на 30-м токене. Если приложение обещает воспроизводимость
(кеш ответов, регресс-тесты) — `f32`.

**6. Токен уходит открытым текстом.** Для кабеля терпимо, для чужого Wi-Fi —
нет. До релиза компаньона в публичных сетях нужен TLS/noise; сейчас честный
режим — только доверенная сеть или кабель.

## 4a. Что добавилось после первой редакции (wire v6 и v7)

**`--peer-run-ahead K` — K токенов за один круг.** В режиме `head` над всем
стеком координатор между токенами не делает ничего, поэтому спрашивать
разрешение на каждый — это лишний круг и ничего больше. Это НЕ спекуляция:
драфт-модель не нужна, вывод совпадает потокенно. Телефон по Wi-Fi:

| K | bonsai 1.7B | 34.7B MoE |
|---|---|---|
| 1 | 13.3 tok/s | 6.5 |
| 4 | 17.5 | 11.5 |
| 8–16 | **23.6** (K=16) | **12.4** (K=8) |

Цена — токены приходят пачками: при K=4 пачка каждые ~230–260 мс, при K=16
рваность заметна глазом. В приложении разумный дефолт — K=4 по Wi-Fi и K=1 по
кабелю, где круг стоит 1.9 мс и экономить нечего.

**`--peer-prefill` — префилл на пире, состояние домой.** Единственный режим,
где провод отрабатывает и уходит: длинный промпт считает десктоп, KV приезжает
на телефон, дальше разговор идёт локально и кабель можно выдернуть. Измерено на
1800-токенном промпте:

| | время |
|---|---|
| префилл на телефоне | 86.9 с |
| префилл на Mac + состояние по USB (f16, 206.5 МБ, 35 МБ/с) | 10.3 + 5.9 = **16.3 с** |

Проверено ровно так, как звучит обещание: воркер и туннель убиты в момент, когда
состояние приехало, — телефон догенерировал всё сам. Состояние стоит **224 КиБ
на позицию** (измерено), так что `--net-dtype f16` здесь решает, окупается ли
перенос: по Wi-Fi те же 206 МБ едут ~14 с.

Экспорт **отказывается** ехать, если состояние он описать не может (q8-хранилище,
Nyström-оверлей, замороженные колонки) — вместо правдоподобного кеша, который
отвечает иначе. Счётчик важности едет вместе с состоянием: его накапливает
каждый слой внимания, и без него дальняя сторона позже вытеснит не те позиции.

**`cortiq peers` — обнаружение.** Схема «искатель спрашивает, воркер отвечает
юникастом», а не «воркер кричит». Причина измерена: широковещание с ноутбука до
Android-телефона **не доходит** (ни `255.255.255.255`, ни подсетевая форма), а
юникаст доходит всегда. Телефон находит десктоп по Wi-Fi за пять секунд. В ответе
— имя файла, `dir_hash`, геометрия, версия провода и нужен ли токен; **самого
токена в сообщении нет**, путь к файлу тоже не уезжает.

## 4b. Телефон-телефон: что мешает, по измерениям

Протокол не знает слова «десктоп»: два телефона делятся точно так же, ролями
координатор/воркер, и в этом смысле режим уже работает. Мешает другое, и оно
проверено, а не предположено:

1. **Друг друга они не найдут.** Воркер, поднятый на телефоне, порт занимает и не
   жалуется — но Mac его в сканировании **не видит**: телефон не получает
   широковещательный запрос. По явному адресу тот же воркер обслуживает нормально
   (проверено: 5.4 tok/s при split 24). Значит для пары телефонов нужен другой
   канал знакомства: QR (на экране «Сервер» он уже рисуется — нужен обратный
   скан), Wi-Fi Direct или BLE.
2. **Run-ahead им не поможет.** Он законен только когда координатор между токенами
   ничего не делает, то есть когда пир держит весь стек. А два телефона делятся
   ровно ради ёмкости — каждый считает свою половину, — и там между токенами
   всегда есть чужой матмул. Лекарство от хвоста Wi-Fi в этой топологии не
   применимо, а хвост удваивается: спят оба радио.
3. **Файл нужен целиком обоим.** Идентичность проверяется по `dir_hash` всего
   файла, поэтому каждый телефон хранит все 12.9 ГБ ради своей половины. Это
   главный практический тормоз, и он не в протоколе, а в том, что идентичность
   не умеет проверяться по диапазону слоёв.
4. **Оценка скорости, из уже измеренного.** Телефон-воркер отдаёт 14 слоёв за
   38 мс по кабелю; у пары каждый считает свою половину, плюс провод: токен
   выходит ~85–100 мс в оптимистичном случае, то есть 5–8 tok/s по Wi-Fi с
   поправкой на губернатор и хвост. Один телефон на этой же модели даёт 14.3.
   Вывод тот же, что и везде: **пара телефонов оправдана только для модели,
   которая не влезает ни в один из них**.

Порядок работ, если браться: сначала (3) — идентичность по диапазону, чтобы
каждый держал свою половину файла; затем (1) — QR-спаривание; и только потом
мерить реальную пару, потому что число решит, ехать ли этому в продукт.

## 5. Чего в рантайме пока нет

Чтобы приложение не проектировалось под несуществующее:

- **Спекулятивного батча.** Для тонкого клиента он и не нужен — там работает
  run-ahead (§4a). Он понадобится ровно в той топологии, где run-ahead запрещён:
  когда координатор держит свои слои. Тогда нужен драфт — модель с MTP-головой;
  на моделях этого стенда `MTP: no`, а layer-skip-спекуляция измерена и мертва.
- **Идентичности по диапазону слоёв.** Обе стороны обязаны держать файл целиком,
  хотя каждая считает свою часть. Для пары телефонов это главный тормоз (§4b).
- **mDNS.** Есть UDP-обнаружение запросом (§4a), и оно работает в направлении
  «телефон ищет десктоп». Полноценный mDNS нужен только чтобы светиться в
  системных сканерах, и он тянет зависимость.
- **Head-режима в `serve --peer`.** Конфиг сэмплера едет один раз в Assign, а у
  сервера он на каждый запрос свой.
- **Шифрования.** Токен по-прежнему уходит открытым текстом.
- **Пользы от GPU на Android.** Он считает верно, но проигрывает CPU;
  включённым он больше не стоит минут, но и не ускоряет. Полный разбор с
  числами, опровержениями и списком работ — `GPU_MOBILE.ru.md`.
- **Head-режима в `serve --peer`.** Конфиг сэмплера едет один раз в Assign, а у
  сервера он на каждый запрос свой; серверный путь остаётся без `head`.
