# Qwen3.5 → быстрый формат: план конверсии без дообучения

Цель: модели структуры qwen3_5 (проверка на Qwen/Qwen3.5-0.8B) конвертируются
в CMF со стеком наших быстрых элементов, декод ×2–3 и выше на длинном
контексте, перенос качества — математикой, не обучением.

Источники: Патент 16 (O(1)-конверсия, US 19/738,763 — замеры в тексте),
Патент 17 (streaming-расширения, draft), Патент 13 (двухполевое кодирование),
vmf_phase-кор (linear_core.rs + converter/heal_vmf_phase.py) и замеры формата.
Экспериментальные ветки, которые не дают выигрыша в текущем стеке, остаются
за пределами конвертера; низкоранговая факторизация предлагается как опция.

## 1. Анатомия цели

Qwen3.5-0.8B: 24 слоя = **18 GDN + 6 full-attention** (интервал 4), hidden
1024, GDN: 16 голов × dk=dv=128, conv4; full: 8 голов × hd 256, 2 KV-головы,
output-gate; FFN inter 3584; **словарь 248320**.

MAC на токен декода (@4k контекста):

| блок | MAC/ток | доля |
|---|---|---|
| 18 GDN-слоёв (микшер 11.1M + FFN 11.0M) | 397M | 46% |
| 6 full-слоёв (проекции 7.4M + FFN 11.0M) | 110M | 13% |
| 6 × KV-attend @4k (8 гол × 4096 × 256 × 2) | 100M | 12% |
| **LM-голова 248320×1024** | **254M** | **29%** |
| итого | ~861M | |

Два наблюдения, которых нет в патентах:
- **Голова — 29% токена уже на 4k** (на коротком контексте — 33%+). Для
  0.8B-класса словарь 248k — главный несущий столб стоимости.
- KV-attend растёт с контекстом: на 32k он был бы ~800M — половина токена.
  Ровно это забирает O(1).

## 2. Стек конверсии — три яруса

### Ярус A: строго без обучения (веса байт-в-байт / чистый PTQ)

1. **Импорт как есть**: GDN несётся 1:1 (валидированный оператор), full —
   обычное внимание. Уже работает (`convert`/`import-gguf`, класс qwen3_5).
2. **Кванты**: q4tp по умолчанию; **q1t (тернарный, training-free)** как
   агрессивный профиль — на GDN-гибриде 14.8B измерено **×2.7 декода**
   (шина ÷~1.9). Для 0.8B ожидание скромнее (фикс-косты): ×1.5–2.0.
   Fisher-CV прогоняем до выбора vbit: при CV < 0.5 двухполевая разрядность
   не даёт выигрыша (замер Патента 13) — у современных плотных моделей так;
   решает métрика, не вера.
3. **O(1) на 6 softmax-слоях** (`--o1 all`): для ЭТОЙ модели уже измерено —
   **ppl ×1.075** (двумя реализациями, расхождение 0.4%), состояние внимания
   всей модели становится константным. Скорость: у 0.6B чисто-softmax декод
   ×3.50 @4k; у гибрида доля attend меньше — оценка +12% @4k, → ×2 к 32k,
   память состояния ÷3–17 по глубине контекста.
4. **Расширения Патента 17 — реализовать в движке (код, не обучение):**
   - **far-only ридаут для гибридов** (клейм 1): ближнее поле несут соседние
     GDN-слои; выкидываем окно из ридаута → оператор O(W·d+S·d+m·dv+m²) →
     O(S·d+m·dv+m²) ≈ **×4 дешевле**, состояние −70%. Гейт: ppl-ratio против
     оконного варианта на этой же модели.
   - **delta-rule запись в far** (клейм 5): та же верность при m 32→16 —
     состояние ÷2, m²-контракция ÷4. Прецедент дельта-правила уже в
     linear_core.rs.
   - **reseal** каждые R позиций — лечит дрейф при неограниченной генерации
     (мелкий слой держит только 0.41 agreement на дрейфе).
5. **Двухступенчатая голова словаря (наш новый элемент, training-free):**
   k-means головы на 4096 центроидов (offline, минуты) → на токене: скоринг
   центроидов (4M MAC) → точный рескоринг топ-кластеров (~16k строк, 16M) →
   argmax/сэмплинг на точных логитах. 254M → ~20M MAC (**−27% токена**).
   Гарантия качества: рескоринг точный; риск — промах кластера для хвостовых
   токенов; гейт — совпадение argmax на корпусе ≥ 99.9%, для сэмплинга —
   KL хвоста. (Для жадного точный вариант: exact-margin остановка.)

**Оценка яруса A (@4k):** MAC 861→~520M (o1 + голова), байты ÷1.5–1.9 (q1t).
Декод **×1.9–2.4**; на 32k — **×2.5–3.2** (o1 забирает растущий attend).
Качество: ppl ×1.075 (o1) × ~1.0–1.05 (q1t по прецеденту) — в пределах
целевого.

### Ярус B: fold на vmf_phase + offline-heal (без пользовательских данных)

18 GDN-микшеров сворачиваются на канонический фазовый кор
(φ(θ)=[cos;sin], состояние 2·nphase×dv):

- fold-инициализация уже написана (`VmfPhaseFoldSource`): thq/thk из
  прореженных q/k-строк, A_log переносится, v/out — настоящие веса;
- микшер: 11.1M → 5.5M MAC (nphase=32) — **−50% микшера, −12% токена**,
  состояние 16×256×128 → 16×64×128 (÷4);
- качество: **phase-коррекция** (CMF_PHASE_MASS) — training-free мост (recall 3→91%
  в режиме fold-до-heal), затем послойная MSE-дистилляция против GDN-учителя
  (`heal_vmf_phase.py`, наши активации, не пользовательские данные; часы на
  одной машине) с двусторонним verdict-gate (healed ≤ scratch+ε и ≤ source+δ).

Строго говоря heal — оптимизация, но: послойная, без датасета задачи, веса
учителя = сама модель. Если требование «вообще без градиентов» жёсткое —
ярус B опускается, ярус A самодостаточен.

### Ярус C: страховка качества

Если длинные генерации ловят петли (известный провал teacher-forced-метрики):
`cortiq fcd` restoration — только norm+FFN конвертированных слоёв,
CE+KL(0.7) к самой модели с точным вниманием, отбор чекпойнта по генерации
(измерено: ×0.80 ppl и 3/3 чистых против петель у чистого CE).

## 3. Сводная арифметика ускорения (декод, 0.8B)

| конфигурация | 4k | 32k | качество (гейт) |
|---|---|---|---|
| базовый q4tp | ×1.0 | ×1.0 (падает абсолютно) | — |
| + o1 (6 слоёв) | ×1.12 | ×2.0+ | ppl ×1.075 (изм.) |
| + голова-shortlist | ×1.45 | ×2.6 | argmax ≥99.9% |
| + q1t | ×1.9–2.4 | ×3.0–3.5 | ppl-гейт по прецеденту |
| + far-only + Δ-rule (P17) | +3–5% | +8–12% | ppl против оконного |
| + vmf_phase fold (ярус B) | ×2.2–2.7 | ×3.3–4.0 | verdict-gate heal |

Целевые «×2–3, а то и больше» достигаются: **×2+ на 4k без обучения
вообще**, ×3+ на длинном контексте; ярус B добирает ещё ~15%.

## 4. Порядок работ

1. Смоук: convert Qwen3.5-0.8B → cmf (q4tp), bench базы + `--o1 all`
   ppl-контроль (ожидаем ×1.075).
2. q1t-профиль + Fisher-CV решение по vbit.
3. Движок: far-only ридаут (env-гейт) → замер ppl/скорости на 0.8B.
4. Движок: delta-rule far (m16) → та же проверка.
5. Голова-shortlist (k-means оффлайн в конвертере, двухступенчатый
   матвек в движке, exact-margin для greedy).
6. Ярус B: fold+phase-коррекция+heal 18 слоёв, verdict-gate.
7. Пакет: профиль `--fast` в конвертере, документация, выгрузка
   образцового Qwen3.5-0.8B-cmf на HF.

Риски: (а) o1 запрещает спекулятивный мульти-токен (вставка необратима) —
не совместим с MTP-профилем одновременно; (б) фикс-косты мелкой модели могут
съесть часть множителя на Metal — лечится whole-token графом (уже есть);
(в) shortlist-голова для сэмплинга с высоким top-k требует большего пула
рескоринга — параметризуем.

## 5. q4t × O(1): реальное ускорение без потери качества

q4t-декод одного токена уже у стены: ядра стримят 88–98 ГБ/с из ~102
на M4 (и 92% шины на 5090) — в самом ядре без потерь брать нечего.
Дальше ускоряет только **амортизация чтения весов на несколько
токенов** — спекулятивный декод с точной верификацией (выход
бит-в-бит для greedy, по распределению — для сэмплинга; rejection
sampling даёт строгую эквивалентность). Замер уже есть: батч-матвек
q4t распаковывает тайл один раз на k токенов — верификация 53→46 мс,
«спекуляция впервые в плюс».

**Развязка несовместимости с O(1).** Патент 16 отключает
мульти-токен из-за необратимой вставки в far. Но состояние O(1) —
константа ~180 КБ на голову (в этом весь смысл оператора):

- **снапшот перед пакетом**: far-аккумуляторы T̂/Ẑ/m_max + мета
  кольца + перезаписываемые слоты окна ≈ 0.2–1 МБ на все o1-слои;
  memcpy ~50 мкс; откат при отказе = restore — бит-в-бит;
- GDN-слои уже несут механизм `*_pair` (полоса 1 коммитит, полоса 2
  в scratch) — расширить до пакета k либо тем же снапшотом
  (состояние компактно);
- **с растущим KV так дёшево нельзя** — O(1) делает спекуляцию
  ДЕШЕВЛЕ, а не запрещает её. Кандидат в continuation Патента 17:
  «speculative-safe streaming attention via bounded-state snapshot»
  — прямо снимает ограничение, продекларированное в родителе.

**Черновики без второй модели (без потери качества по построению):**
1. **MTP-голова** — у Qwen3.8-27B она уже в файле (self-drafting);
2. **prompt-lookup / n-gram** — бесплатно, силён на коде и цитатах;
3. для 0.8B — черновик из собственных ранних слоёв (self-spec) или
   отдельная 0.3B той же семьи.

Арифметика (M4, 27B q4t, 172 мс/токен): верификация пакета k=4 при
распаковке-один-раз ≈ 200–220 мс; приёмка 60–75% (по кампании DSV4)
→ эффективные **×1.8–2.4 поверх любых остальных множителей**, и
качество не тронуто по построению.

**Остальное для q4t без потерь:**
- far-only ридаут (P17) — ×4 на самом o1-операторе; гейт — ppl
  против оконного варианта на LM (прокси-абляция уже в его пользу);
- голова с сертификатом: низкоранговый скетч + построчная граница
  ошибки ‖W_i‖·‖x−x̃‖ — если маржа argmax сертифицирована, полная
  голова не считается ВООБЩЕ (точный greedy, ноль риска); иначе —
  полный матвек. На жадном декоде срабатывает почти всегда;
- q4tp как опция «−7% байт за +0.1% ошибки» — строго говоря не
  lossless, держим отдельным профилем.
