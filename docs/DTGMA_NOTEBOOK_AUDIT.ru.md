В папке есть сильные инженерные наработки: DTG-MA-маски над общими

Наиболее полезный рецепт для новой статьи находится в

индикаторов, ответ только на assistant-части, DTG-MA → FCD → defrag. Его
нельзя копировать вместе с оценкой: один и тот же первый фрагмент `test_data`
используется внутри итеративного выбора лучшей маски, а потом показывается как
финальный результат. В новой версии нужны отдельные train/validation/test.

## Разбор самых заметных результатов

### 1. Прямой генеративный trading skill: 43% → 52%

Файлы:

- `colab_dtgma_trading_skill.ipynb`;
- `colab_dtgma_trading_skill_1.7b.ipynb`;
- варианты 14B и 32B.

Полезная часть рецепта:

- ETH/USD, часовые свечи, история до двух лет;
- 48 свечей преобразуются в компактный набор momentum/trend/volatility,
  поддержки/сопротивления, свечи и объёма;
- target — знак изменения следующего close, строго `UP` или `DOWN`;
- assistant-ответ — JSON, prompt-токены маскируются в loss;
- одна общая маска применяется к `gate_proj`, `up_proj` и входу
  `down_proj`;
- после поиска маски последние четыре FFN проходят FCD;
- заявленный итог в summary: 43% → 52%, pruning 72%.

Почему эти 9 п.п. нельзя перенести в статью как доказанный test-результат:

- `iterative_prune_train(..., test_data=...)` на каждой итерации оценивает
  первые 100 элементов того же `test_data`;
- checkpoint выбирается с учётом результата на этих 100 элементах;
- финальные 52% снова измерены на них же;
- в выводах промежуточный реальный pruning 63,94%, а summary пишет 72%;
- видимая стадия «defrag» разворачивает wrappers, но не подтверждает
  физическое уменьшение форм и размера файла;
- summary 43/52/72 практически одинаков у вариантов разных размеров модели,
  хотя промежуточные логи различаются.

Это хороший прототип технологии, но selection-contaminated оценка.

### 2. Contrastive 1.7B: «76%», которое блокнот сам опроверг

`colab_ethusd_contrastive1.7b.ipynb` показывает 76% на 200 примерах. В том же
блокноте есть правильная диагностика:

- после перестановки prompts: 76%;
- с одним постоянным prompt: 76%;
- после замены UP ↔ DOWN: 78,5%;
- реальный роутинг без знания правильного ответа: route accuracy 36%,
  prediction accuracy 32%;
- собственный verdict блокнота: `NO SIGNAL`.

Причина — teacher-forced выбор маски по известному answer. Эта цифра измеряет,
насколько маска объясняет уже подставленный ответ, а не способность предсказать
его по свечам.

### 3. v18 двухступенчатый роутер: 66,4%

`colab_ethusd_dtgma_v18_1_7bv4.ipynb` делит задачу на GATE
`TRADE/NO_TRADE` и DIRECTION `UP/DOWN`. На первых 256 test-примерах показано
66,4%, но confusion matrix содержит только:

- 170 `NO_TRADE → NO_TRADE`;
- 33 `UP → NO_TRADE`;
- 53 `DOWN → NO_TRADE`.

То есть роутер выдал `NO_TRADE` для всех 256 случаев. 66,4% — доля
мажоритарного класса, не направленческая точность. Для бинарной статьи без
FLAT этот результат неприменим.

Более ранние v18 дают 48–67% routing accuracy, но test передаётся в функцию
обучения и многократно печатается во время разработки. В ряде запусков также
нет сохранённого финального вывода. Эти версии полезны как эволюция
reconstruction router, не как locked-test benchmark.

### 4. Patent 3/v20: высокие цифры при частичном покрытии

В `colab_mask_generation_v20/colab_btc_v1.ipynb` сохранено:

- UP-маска: 70,2% win rate при coverage 10,7% (161 пример);
- DOWN-маска: 61,0% win rate при coverage 10,9% (164 примера).

Это интересный результат **условной специализации режимов**. Но 70,2% нельзя
называть общей accuracy классификатора: маска выигрывает роутинг только на
10,7% characterization-набора, а остальные режимы обслуживают другие маски.
В `patent3_discovery_v1/v2` встречаются 79–93%, но coverage там от 0,1 до
4,7%; у некоторых «лучших» масок profit factor ниже единицы.

Плюс для методологии v20: train и characterization разделены во времени
(`train_data[:15000]`, затем gap 48 и characterization). Минус: по
characterization одновременно назначаются действия маскам и выбираются лучшие
маски. Для публикации после этого нужен ещё один независимый test-период.

Отдельная проверка сохранённых outputs выявила, что 22 блокнота разных активов
несут один и тот же вывод. Поэтому per-asset цифры нужно пересчитать с нуля.

## Какие метрики нельзя смешивать

| Метрика | Что она означает | Можно ли назвать общей точностью? |
|---|---|---|
| full binary accuracy | правильный UP/DOWN на каждой test-свече | да |
| balanced accuracy / macro-F1 | качество обеих сторон при дисбалансе | да, вместе с confusion matrix |
| per-mask win rate | знак return только там, где победила данная маска | нет, без coverage |
| TRADE/NO_TRADE gate accuracy | способность отфильтровать сделки | нет, это другая задача |
| teacher-forced routing | выбор маски после подстановки ответа | нет, это не прогноз |
| PPL | насколько модель объясняет текст/ответ | нет, но это полезный training gate |
| backtest PnL/Sharpe | результат конкретной торговой логики | нет; нужны комиссии и отдельный test |

## Почему старый `confidence` не является уверенностью в UP/DOWN

В `colab_dtgma_trading_skill_1.7b.ipynb` confidence вычисляется так:

```python
first_token_logits = outputs.scores[0][0]
probs = torch.softmax(first_token_logits, dim=-1)
conf = probs.max().item()
```

Но ответ модели начинается с JSON, то есть первый предсказываемый токен —
открывающая фигурная скобка/начало JSON, а `UP` или `DOWN` появляется позже.
Поэтому сохранённые `0.9836 ± 0.0202` означают примерно «модель уверенно начала
JSON», а не «вероятность направления 98,36%». Это объясняет, как confidence
около 0,98 сосуществует с directional accuracy 52%.

В новой реализации коэффициент определён однозначно:

```text
p = softmax([logit(DOWN), logit(UP)])
prediction = argmax(p)
confidence = max(p)
```

Для любого confidence-среза обязательно публикуются coverage и число
наблюдений. Уверенность без calibration/reliability table не считается
доказательством качества.

рыночный quality gate данный checkpoint не прошёл.

## Рецепт, который стоит перенести в статью

Для короткой и повторяемой статьи выбран один вопрос: **будет ли следующий
часовой close BTCUSDT выше или ниже текущего**.

1. Источник — только закрытые Binance Spot 1h свечи за фиксированный год.
2. Каждая запись использует ровно 48 прошлых свечей.
3. `UP`, если `close[t+1] > close[t]`, иначе `DOWN`; FLAT-класс отсутствует,
   ни одна неоднозначная свеча не удаляется.
4. Prompt компактный, как в удачном 1.7B-прототипе: returns, EMA/MACD,
   RSI/CCI/ROC, ATR/HV, Bollinger, support/resistance, candle/volume и хвост
   последних изменений цены. Сырые 48 строк по тысяче токенов не нужны.
5. Разбиение 70/15/15 по времени с purge-gap 49 часов. Validation выбирает
   маску и FCD checkpoint; test не открывается до конца.
6. На одинаковых test-примерах сравниваются majority, momentum, чистая
   Qwen3.5-2B q4tp и q4tp+CMF skill.
7. Публикуются accuracy, balanced accuracy, macro-F1, confusion matrix,
   распределение ответов, paired block-bootstrap 95% CI, размер и SHA-256.
8. Положительным результат считается только если skill лучше q4tp и нижняя
   граница CI не противоречит заявлению. PPL≈2 по двум labels само по себе не
   является успехом.
9. Отдельный `.skill.cmf` проверяется через `apply`; применённый файл должен
   давать те же предсказания, что и запечённый специалист.
