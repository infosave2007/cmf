# Генеративные модальности в CMF: звук, картинки, видео

Планирование на будущее (июль 2026). Цель — локальная генерация в
мобильном приложении (cmfmobile) на моделях в формате CMF, без облака.
Критерий отбора моделей: открытые веса, лицензия позволяет
редистрибуцию, влезает и реально работает на телефоне класса
Snapdragon 778G (4–8 ГБ RAM) — флагманы получают «большой» тир.

## Фаза 1 — звук (TTS): минимальная дельта, максимальный эффект

Современные лучшие маленькие TTS — это обычные LLM, генерирующие токены
аудио-кодека вместо текста. Трансформер, токенизатор, сэмплер,
квантование и GPU-графы CMF переиспользуются как есть; новое — только
декодер кодека (небольшая конв-сеть) и FFI-выход PCM.

### Модели

| Модель | Параметры | Бэкбон | Кодек | Лицензия | Телефон |
|---|---|---|---|---|---|
| **NeuTTS Air** | 748M | **Qwen 0.5B** (наш тестовый бэкбон!) | NeuCodec, один кодбук | Apache 2.0 | q4t ≈ 400 МБ — да, вкл. 4 ГБ устройства |
| neutts-nano | меньше | Qwen | NeuCodec | Apache 2.0 | да |
| Orpheus-3B | 3B | Llama | SNAC (мультикодбук) | открытая | флагманы, q4 ≈ 1.9 ГБ |
| CSM-1B (Sesame) | 1B | Llama | Mimi | открытая | да, диалоговый стриминг |
| Kokoro-82M | 82M | StyleTTS2 (НЕ LLM) | — | открытая | не наш путь: чужой зоопарк операторов |

Приоритет: **NeuTTS Air** — тот же Qwen2.5-0.5B, который движок гоняет
с первого дня; мгновенное клонирование голоса по 3-сек образцу
(аудио-префикс из токенов кодека); официально позиционируется под
телефоны, реалтайм на CPU через llama.cpp — наш движок на этом бэкбоне
быстрее.

### Работы по движку/формату

1. **NeuCodec-декодер на Rust** — конв-стек (conv1d в движке уже есть —
   ShortConv/GDN); веса декодера — новая секция CMF (мелкая, можно f16).
2. Конвертер: neutts-air/nano → один .cmf (бэкбон + секция кодека +
   токенизатор).
3. FFI: `cortiq_tts(handle, text, speaker_ref, cb)` → PCM-чанки
   (стриминг в плеер приложения).
4. Замер: частота токенов кодека vs tok/s на 778G/8G3 — реалтайм или
   офлайн-рендер по устройству.

## Фаза 2 — картинки: основная цель — Lumina-Image 2.0 (в работе)

РЕШЕНИЕ (25.07.2026): Sana/Sana-Sprint отпали — лицензия research-only
(NVIDIA NSCL). Основной кандидат — **Lumina-Image 2.0 (2.6B)**:
Apache 2.0 целиком, Next-DiT (обычные трансформер-блоки), текст-энкодер
Gemma-2-2B (декодер-онли LLM — наш стек), FLUX-VAE (Apache от schnell).
В q4: DiT ~1.4 ГБ + Gemma ~1.4 ГБ + VAE ~0.2 ≈ 3 ГБ — флагманы 12 ГБ+
и десктоп. Десктоп-топ вторым этапом: FLUX.1-schnell (Apache, 12B) на
той же диффузионной базе.

Прогресс:
- [x] **FLUX-VAE-декодер на Rust** (`cortiq-engine/src/vae.rs`):
  conv2d/GroupNorm/SiLU/spatial-attention/upsample, загрузка из
  diffusers `vae/`; паритет с numpy-референсом (`python/vae_ref.py`,
  `tests/vae_parity.rs`) на реальных весах: max|Δ| = 6.6e-6.
  Ядра пока наивные (8×8 латент → 64×64 за 4.3 с) — im2col+GEMM позже.
- [x] **Gemma-2-2B forward** (`textenc.rs`): полный форвард энкодера
  (embed·√h, (1+w)-RMSNorm, сэндвич-нормы, GQA + softcapping, GeGLU),
  проекции батчами через GEMM; паритет с numpy-референсом
  (`python/gemma_ref.py`) на весах Lumina: rel max|Δ| = 1.4e-4;
  тёплый encode 8 токенов — 0.29 с (холодный 15 с = пейдж-ин 10.4 ГБ
  f32 — решается квантованной упаковкой в CMF).
- [x] Скорость VAE, раунд 1: conv → полосный im2col + gemm_nt
  (Accelerate/AMX), attention mid-блока на GEMM: крошечный декод ×29
  (4.3 → 0.15 с); 512px — 8.1 с, 1024px — 36 с на CPU M4 (стены — формы
  GEMM и поэлементные проходы; следующий большой шаг — Metal).
- [x] **Next-DiT forward** (`dit.rs`): полный форвард денойзера
  (patchify + x_embedder, timestep-MLP, caption-embedder,
  context/noise-refiner, 26 AdaLN-слоёв с tanh-гейтами, 3-осевой
  комплексный RoPE, qk-нормы per-head, SwiGLU 9216, norm_out
  LayerNorm 1e-6); паритет с numpy-референсом
  (`python/nextdit_ref.py`, `tests/dit_parity.rs`) на реальных
  весах: max|Δ| = 2.1e-5 (rel 1.5e-5).
- [x] **Flow-matching цикл + e2e текст → картинка** (`imagegen.rs`,
  CLI `cortiq imagine`): шаблон промпта с `<Prompt Start>`, Gemma
  hidden_states[-2], сигмы linspace(1,1/N,N) через сдвиг
  σ'=6σ/(1+5σ), модель на t=1−σ, CFG с норм-рескейлом по строкам и
  сменой знака перед Euler-шагом; компоненты грузятся стадийно
  (пик RSS = один компонент, не сумма). Попутно фикс токенизатора:
  BOS берётся из post_processor-шаблона (у Gemma в vocab и `<bos>`,
  и `<s>` — порядок added_tokens выбирал не тот); golden-тест 40 id
  против HF tokenizers + e2e-смоук (`tests/imagegen_smoke.rs`).
- [x] **Один .cmf на весь пайплайн** (`cortiq imagine-pack`,
  `imagepack.rs`): te.* + dit.* + vae.* + токенизатор в VOCAB-секции
  + конфиги как U8-тензоры; проекции q4t/q8, AdaLN-модуляция и
  эмбеддинги всегда q8, VAE f16, нормы f32. 19 ГБ диффузерс-дерева →
  **3.2 ГБ одним файлом** (5.9×). Рантайм гоняет квантованные
  проекции прямо с mmap через батчевые ядра движка (QTensor::matmat)
  — f32-путь из каталогов не тронут (parity-тесты бит-честные).
  Попутно q4t_matmat получил wide-batch AMX-арм (деквант-тайлы +
  sgemm, как у q8): яблоко 256px/18 шагов/CFG — 203 с (f32-каталоги)
  → 144 с (.cmf), первый шаг на 8-й секунде; PSNR к f32-рендеру
  29.3 dB (визуально идентично).
- [x] **GEMM-внимание DiT**: наивный последовательный цикл заменён
  на три GEMM на голову (scores=Q·Kᵀ, пул-параллельный softmax,
  P·V) — то же яблоко **59 с** (было 144; итого ×3.4 за день),
  паритет 1.45e-5. Снята стена глубины: 512px (1064 токена) на CPU
  стал практичным.
- [ ] Скорость: conv через наши GEMM, GPU-графы для DiT-шага

## Прочие кандидаты (справочно, было «Фаза 2»)

Кандидаты, влезающие в телефон:

| Модель | Параметры | Архитектура | Текст-энкодер | Статус весов |
|---|---|---|---|---|
| **Sana-0.6B** (NVIDIA) | 0.6B | DiT с **линейным вниманием** | Gemma-2-2B (тяжёлый) | открыты |
| SD-Turbo | 0.86B UNet | UNet, 1–4 шага | CLIP-L 123M (лёгкий) | открыты |
| SnapGen++ | 0.4B | mobile-DiT, 1024px за 1.8с на iPhone | — | **не выложены** (следить) |
| PixArt-α | 0.6B | DiT | T5-XXL 4.7B | энкодер не влезает |

Sana в q4 целиком ≈ 1.5–1.8 ГБ (DiT+Gemma+DCAE) — ок для 8 ГБ
телефонов; линейное внимание — наша сильная сторона. SD-Turbo — меньше
всего шагов и крошечный энкодер, но UNet = много новых конв-ядер.

### Работы по движку/формату

- Не-каузальный (encoder) режим внимания — для CLIP/Gemma-энкодера.
- Диффузионный цикл: timestep-эмбеддинги, AdaLN-модуляция,
  flow-matching/few-step scheduler.
- Декодер латентов (DCAE/VAE) — конв-сеть покрупнее, CPU+GPU ядра.
- Новые типы слоёв в конвертере; Metal/wgpu-графы для DiT-шага.

## Фаза 3 — видео: пока нет

Самые маленькие открытые (Wan2.1-1.3B, LTX-2B) считают клип минутами
даже на десктопном GPU; 3D-VAE прожорлив по памяти. На телефонах видео
генерят только закрытые вендорские модели (Honor Image-to-Video).
Решение: отложить, пересматривать раз в квартал.

## Порядок исполнения

1. NeuCodec-декодер + секция формата + конверт NeuTTS Air (звук
   end-to-end в CLI).
2. `cortiq_tts` в FFI + интеграция в cmfmobile (плеер, выбор голоса).
3. Orpheus-3B как флагманский тир (SNAC-декодер).
4. Фаза 2: прототип Sana на десктопе (Metal), затем мобильная оптимизация.
