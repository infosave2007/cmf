# Сжатие языковой модели под задачу: засветка, свёртка с refit, лечение, маски DTG-MA и порядок NVG ↔ DTG-MA

*Олег Юревич Кириченко. Реализация и измерения — движок cortiq, формат CMF (ветка `compress`), 27–28 октября 2026 г.*

> **Перед публикацией.** Патент 12 (AWNP) на момент написания готовится к подаче в USPTO. Статья ссылается на него
> по названию и описывает только то, что использовано в этой работе. Публичное раскрытие до подачи может повлиять
> на патентоспособность за пределами льготного периода США.

## Аннотация

Общая языковая модель тратит большую часть весов на то, что конкретной задаче не нужно. Мы строим одну
команду, `cortiq compress SOURCE.cmf PROMPTS.jsonl OUTPUT.cmf --ratio R`, которая превращает общую модель в
специалиста под список промптов пользователя. Конвейер:

1. Учитель отвечает на промпты: сама модель, старшая модель или модель за OpenAI-совместимым API.
2. По ответам видно, какие нейроны FFN задача использует («засветка»).
3. Лишние нейроны удаляются, а их вклад переносится в оставшиеся решением в замкнутой форме («свёртка с refit»).
4. Модель доучивается на ответах учителя («лечение»).
5. Отложенные ответы оценивают результат.

Ширину слоёв можно выбирать и обученной маской DTG-MA (Патент 2). Для моделей MoE удаляются эксперты, которых
задача не выбирает. Тяжёлые стадии работают на GPU-тренере: на NVIDIA через Vulkan и тензорные блоки, на Apple
Silicon через Metal и simdgroup-матрицы.

На Qwen3.5-0.8B и 2B получены следующие результаты.

- **Refit — главный рычаг структурного сжатия.** Он вдвое снижает ошибку выхода FFN по сравнению с простым срезом.
- **Выбор нейронов почти не влияет на итог.** Обученная маска DTG-MA даёт лучшую свёртку, чем засветка, но после
  лечения преимущество исчезает: на этих моделях лечение стирает разницу в выборе.
- **Маски на квантованной модели работают как ремонт квантования.** На модели, закодированной NVG до 2 бит на вес,
  маски DTG-MA закрывают сильнее всего испорченные нейроны. KL к учителю падает с 2.17 до 1.23 без единого шага по
  весам. Порядок «сначала NVG, потом DTG-MA» при равном размере лучше обратного: test NLL 1.618 против 1.931 на
  2 битах, 1.277 против 1.340 на 3 битах.
- **У малых плотных моделей сжатие нужно набирать квантованием, а обрезку применять только сверх него.**

## 1. Задача

Дано: модель в CMF и файл промптов задачи. Нужно получить файл заданного размера (доля `R` от исходного в том же
кодеке), который на этой задаче ведёт себя как исходная модель. Требования такие:

- одна команда, без ручных стадий;
- прогресс и оценка оставшегося времени видны на каждой стадии;
- прерванный запуск продолжается с места остановки;
- квантование — отдельный шаг пользователя: выход остаётся в кодеке исходника;
- глубина (число слоёв) не сокращается, только ширина FFN и эксперты MoE;
- формат CMF хранит ширину каждого слоя сам, поэтому удалённые нейроны физически исчезают из файла. Дефрагментация
  и выравнивание ширин не нужны.

## 3. Метод

### 3.1 Данные учителя

Учитель отвечает на каждый промпт. По умолчанию это сама модель. Можно взять другую CMF с тем же токенизатором
или модель за любым OpenAI-совместимым API (`openrouter:`, `openai:`, `api:` + `--api-base`). Ответы API приходят
текстом и превращаются в токены токенизатором сжимаемой модели. Рассуждение (`reasoning` / `reasoning_content` /
`<think>`) ставится перед `</think>`, как его продолжает шаблон ученика. Ответ, оборванный лимитом токенов, хранится
как усечённая запись без токена конца. Записи делятся на train/val/test по промптам (80/10/10, стратификация по
категориям). Test не видит ни одна стадия сжатия.

### 3.2 Засветка

Исходная модель прогоняется по ответам учителя. Для входа `down_proj` каждого слоя накапливается грамиан
`Σ = Σ_t a_t a_tᵀ` (раздельно на train и val). Важность нейрона j:

`I_j = ‖W_down[:, j]‖² · ⟨a_j²⟩`,

то есть вклад нейрона в выход слоя на данных задачи. Это взвешенная активациями важность канала в смысле
Патента 12, только без SVD: оценивается сам выход `down_proj`.

### 3.3 Свёртка с refit

Слой оставляет нейроны S и удаляет P. Вместо простого среза вклад удалённых нейронов регрессируется на оставшиеся:

`W_down' = W_S + W_P · Πᵀ`,  `Π = (Σ_SS + ε·I)⁻¹ Σ_SP`,

где ε — относительный ридж. Ридж и сам выбор «refit или срез» решаются по ошибке выхода на val. Ошибка кандидата
считается через грамиан удалённых столбцов `G = W_Pᵀ W_P`:

`‖W_P − A‖²_Σ = ⟨G, Σ_PP − 2·Πᵀ Σ_SP + Πᵀ Σ_SS Π⟩`.

Эта форма обходится в k²p + 2kp² операций вместо h(k² + kp + p²) + hkp на явное построение `A = W_P Πᵀ`.

### 3.4 Лечение

Учатся веса MLP хвостовых слоёв: f32-копии весов с Adam, f16-плоскости обновляются каждый шаг. Слои ниже заморожены
(FCD), обратный проход до них не идёт. Лосс — смесь `α·CE` по тексту учителя и `(1−α)·KL` к top-64 распределению
несжатого исходника; при α = 1 это лечение без дистилляции (Патент 12, §4.7). Лучшая контрольная точка выбирается
по val.

### 3.5 Маски DTG-MA внутри GPU-тренера

Между SwiGLU и `down_proj` каждого слоя стоит гейт: `h ↦ h ⊙ s`, где `s = σ(m)`. Прямой и обратный проходы гейта
сделаны двумя слитыми ядрами. Градиент `∂L/∂s_j = Σ_t ∂L/∂(h s)_{t,j} · h_{t,j}` считает колоночная редукция на
GPU. Adam по логитам m (на 0.8B это 86 016 чисел) работает на хосте. L1-давление `λ·σ(m)` растёт на каждой оценке,
пока не достигнута целевая разреженность. Каждые 25 шагов жёсткая маска `σ(m) > 0.5` проверяется на val, и берётся
первая контрольная точка у цели. По обученным логитам один общий порог задаёт ширину каждого слоя (кратную 128), а
порядок логитов выбирает сами нейроны. Дальше идут свёртка и лечение, как в §3.3–3.4.

Проверка градиента на настоящей 0.8B. С открытыми гейтами сеть побитово совпадает с сетью без гейтов. Градиент
гейта сходится с конечной разностью: в последнем слое до 0.3 %, в слое 0 до 3.5 % на шаге 0.08. Шаг 0.02 в слое 0
даёт разброс до 33 % из-за округления f16 в прямом проходе, так же ведёт себя уже проверенный градиент нормы слоя 0.

### 3.6 Модели MoE

Засветка считает, как часто маршрутизатор выбирает каждого эксперта на ответах задачи. В файле остаются эксперты,
которые набирают нужную долю маршрутов; порог подбирается бисекцией под `R`. Маршрутизатор режется до оставшихся
и выбирает среди них, как прежде.

## 4. Инфраструктура

- **Стадии S0–S6** — отдельные процессы с кэшем по ключу входов. Повторный запуск продолжает с первой
  незавершённой стадии.
- **GPU-тренер на NVIDIA** (Vulkan, кооперативные матрицы 16×16) на Qwen3.5-0.8B, RTX 5090:
  - лечение — 99 с против 6308 с на CPU;
  - засветка — 45 с против 320 с;
  - test NLL — 10 с против 230 с, совпадает с рантаймом до 2·10⁻⁴.
- **GPU-тренер на Apple Silicon** (Metal через wgpu, simdgroup-матрицы 8×8). Генераторы GEMM и внимания обобщены
  на фрагмент 8×8. Ядра GDN и обучения знаков работают на 32-битных SIMD-группах. Шаг лечения 0.8B (2 окна × 2048
  токенов, MLP всех слоёв) на M4:

  | что включено | с/шаг |
  |---|---|
  | запасные f32-ядра внимания и GDN | 47 |
  | + внимание на simdgroup-матрицах 8×8 | 27.6 |
  | + ядра GDN на SIMD-группах | 17.4 |
  | + тайл GEMM 64×64×32 (3.0 TFLOPS вместо 1.7) | 12.2 |

  Тот же `compress` на Mac даёт исходную 0.1891 и свёртку 0.3642; на 5090 — 0.1891 и 0.3643.
- **Учитель через API.** Qwen3.8-27B через OpenRouter, кодовые промпты:
  - 160 ответов без рассуждения, 32 запроса параллельно: 419 тыс. токенов за 2 минуты, $0.91;
  - с рассуждением и лимитом 8192 токена 9 ответов из 12 обрываются внутри рассуждения;
  - цена провайдеров одной модели различается в 2.5 раза, часть отдаёт её в fp4. Выбор самого дешёвого провайдера
    с 8/16-битными весами снижает цену токена на 30 %.

### 5.5 Выбор нейронов: засветка против маски DTG-MA

Обучение маски на GPU занимает 0.37 с на шаг против 16.7 с у реализации `skillbake` на хосте (в 45 раз быстрее).
Вся маска для 0.8B обучается за ~3 минуты вместо 70. При линейном росте L1-давления прореживание застревало на 15 %:
градиент задачи на оставшихся гейтах растёт быстрее штрафа. При росте ×1.5 за оценку цель 25 % достигается за
325 шагов.

| модель, цель | свёртка: засветка / DTG-MA | после лечения: засветка / DTG-MA |
|---|---|---|
| 0.8B, FFN 75 % | 0.364 / **0.339** | **0.281** / 0.282 |
| 0.8B, `--ratio 0.9` | 0.394 / **0.372** | **0.305** / 0.310 |
| 2B, FFN 75 % | 0.320 / 0.320 | **0.255** / 0.261 |

Маска выбирает нейроны лучше засветки: свёртка лучше на 0.8B. Но лечение выравнивает результаты. Засветка
дешевле и остаётся по умолчанию.

### 5.6 Порядок методов: NVG и DTG-MA

0.8B, FFN 75 %, оба варианта одного размера.

- **A, DTG-MA → NVG.** Сжатая маской f16-модель кодируется NVG, затем метрика доучивается `nvg-train`.
- **B, NVG → DTG-MA.** Кодируется вся модель, затем маски DTG-MA учатся на NVG-модели тем же KL к учителю, закрытые
  нейроны вырезаются прямо из бинарных low-rank тензоров (строки `gate`/`up`, столбцы `down`, без перекодирования),
  затем метрика доучивается так же, как у A.

Чтобы размеры совпали, FFN ветки B кодируется с битностью, делённой на 1.074. Тогда после выреза ранги тензоров
равны рангам ветки A. Учитель, данные (тексты задачи, 2 эпохи × 262 тыс. токенов) и кэш top-k у веток общие.

| битность, размер | ветка | test NLL | зацикливаний | KL на отложенных данных |
|---|---|---|---|---|
| 2 бит/вес, 0.398 ГБ | A без дообучения | 2.587 | 16/16 | 2.217 |
| | A после `nvg-train` | 1.931 | 16/16 | 1.577 |
| | B сразу после выреза | 1.681 | 16/16 | 1.225 |
| | **B после `nvg-train`** | **1.618** | 14/16 | **1.160** |
| 3 бит/вес, 0.437 ГБ | A после `nvg-train` | 1.340 | 7/16 | 0.887 |
| | **B после `nvg-train`** | **1.277** | 13/16 | **0.774** |

Исходная модель: test NLL 0.189.

**Главное наблюдение.** На NVG-модели маски DTG-MA не портят, а чинят. Без единого шага по весам, только закрыв
27 % нейронов, они снижают KL к учителю с 2.17 до 1.23. Маска находит нейроны, которые кодирование исказило
сильнее всего, и удаляет их. Порядок «сначала NVG» выигрывает при равном размере, но выигрыш тает с ростом
битности: −0.31 нат на 2 битах, −0.06 нат на 3. На 3 битах ветка B при этом зацикливается чаще (13/16 против
7/16).

## 6. Открытия работы

1. **Refit, а не выбор нейронов, определяет качество свёртки.** Перенос вклада удалённых нейронов в замкнутой
   форме вдвое снижает ошибку выхода FFN. Отключение refit ухудшает NLL сильнее любого другого параметра.
2. **Лечение стирает разницу в выборе нейронов.** Обученная маска DTG-MA выбирает лучше засветки, но после
   лечения результаты совпадают (0.8B) или засветка чуть впереди (2B).
3. **Обрезка как ремонт квантования.** Маски DTG-MA на модели, закодированной NVG ниже обычной точности, удаляют
   сильнее всего испорченные кодированием нейроны и снижают KL к учителю почти вдвое без обучения весов. Отсюда
   порядок для гибрида: сначала квантование, затем маска и вырез.
4. **Давление на маску должно расти геометрически.** Линейное расписание L1 останавливает прореживание на ~15 %.
5. **У малых плотных моделей сжатие набирается квантованием.** Обрезка ширины дорога, и её место — сверх кванта.
6. **Риж свёртки почти всегда 0.1.** Это подсказка, что оптимальный риж лежит выше прежней сетки. Новая сетка
   `0.03, 0.1, 0.3` даёт тот же результат на одну факторизацию дешевле.

## 7. Ограничения

- Только Qwen3.5-0.8B и 2B (плюс одна MoE), один набор задач (код), одно зерно. Тест — 34 записи на 0.8B.
  Различия меньше ~0.01 нат лежат в пределах шума.
- NLL на ответах учителя — не качество решения задачи. Для кода нужна проверка исполнением.
- Ветки эксперимента о порядке на 2–3 битах на вес сломаны в абсолютном смысле: они зацикливаются почти везде.
  Порядок методов измерен, пригодной модели на этой битности пока нет.
- На M4 лечение 0.8B упирается в GEMM на ~3 TFLOPS и длится часы. Полные прогоны делались на RTX 5090.

## 8. Воспроизведение

```bash
# задача → сжатая модель (учитель — сама модель)
cortiq compress Qwen3.5-0.8B.cmf prompts.jsonl q08-task.cmf --ratio 0.9

# выбор нейронов обученной маской DTG-MA (Патент 2)
cortiq compress Qwen3.5-0.8B.cmf prompts.jsonl q08-dtgma.cmf --ffn 0.75 --select dtgma

# учитель через API
OPENROUTER_API_KEY=… cortiq compress Qwen3.5-0.8B.cmf prompts.jsonl q08-27b.cmf --ratio 0.9 \
    --teacher openrouter:qwen/qwen3.8-27b --no-think --api-concurrency 32

# порядок NVG → DTG-MA: кодирование, маска и вырез, обучение метрики
cortiq convert --model Qwen/Qwen3.5-0.8B --quant blr --bpw 2.0 --blr-paths 2 --calib task.txt --output nvg.cmf
cortiq nvg-train nvg.cmf --teacher q08-q8_2f.cmf --calib task.txt --tokens 262144 --epochs 2 \
    --mask-keep 0.75 --output nvg-dtgma.cmf

# сравнение нескольких моделей на тех же test-записях
cortiq compress Qwen3.5-0.8B.cmf task.tdata run.cmf --ffn 0.75 --compare nvg-dtgma.cmf --compare other.cmf
```
