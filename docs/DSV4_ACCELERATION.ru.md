# DeepSeek V4 Flash: q4tp/q2tp на одной GPU

Актуально для `cortiq` после 0.5.100. Стенд последней проверки: NVIDIA A40
46 ГиБ, Vulkan, драйвер 580.173.02, 7.65 CPU-ядер, модель
`infosave/DeepSeek-V4-Flash-0731-cmf`.

## Обычный запуск

Внутренние ручки DeepSeek V4 выставлять не нужно:

```sh
XDG_RUNTIME_DIR=/tmp cortiq run dsv4-flash-q4tp.cmf --prompt '...'
XDG_RUNTIME_DIR=/tmp cortiq bench dsv4-flash-q4tp.cmf --tokens 128 --core
```

Движок сам:

- включает GPU и chain-of-one;
- на Vulkan/q4tp создаёт один общий сегментированный банк экспертов и живую
  таблицу `(слой, эксперт) → слот`;
- оставляет для поздних пиков attention/KV автоматический запас 2–4 ГиБ;
- разрешает слоям занимать общие свободные слоты, но защищает минимальный
  рабочий набор каждого слоя от циклического вытеснения;
- измеряет host-to-VRAM полосу и выбирает квоту LRU-refill;
- использует нативный формат MTP-драфта: q4 для q4tp и q2 для q2tp, только
  если геометрический VRAM-гейт заранее выделил для него место;
- выбирает размер batched verify-chain по VRAM;
- держит до 40 экспертов каждой стадии драфта — это измеренный предел плато
  acceptance, более широкий пак только добавляет работу;
- исполняет четыре строки gate/up с одной общей загрузкой активации. Для
  q2tp этот же четырёхстрочный путь теперь используется и в обычном
  chain-of-one, и в batch verify.
- не загружает соседние task-маски: полный router остаётся неизменным, а
  `CMF_MOE_MASK` допускается только как явный диагностический A/B;
- до окна `bench --core` прогревает не только forward, но и настоящий decode,
  включая ленивую загрузку DSpark-пака.

Переменные `CMF_DSV4_*` и `CMF_DSPARK_*` сохранены как диагностические
override для A/B, но не являются пользовательским API запуска.

## Измерения q4tp

`bench --core`, steady-state, один процесс:

| режим | A40, ток/с | корректность |
|---|---:|---|
| старый дефолт | 0.665 | точный роутинг |
| exact dynamic LRU, 24.08.2026 | **1.5–1.8** | полный роутинг; cold expert точно досчитывается на CPU |
| hard task-mask 97,5%, без MTP | 11.0 | эксперимент отклонён: меняет модель |
| hard task-mask 92,5–95% + MTP | 19.5–21.5 | эксперимент отклонён: длинная генерация разрушает качество |

В masked-эксперименте обнаружена отдельная ошибка: speculative-блок мог
закончиться за границей `max_tokens` (66 токенов на запрос 64). Теперь
последний verify сразу ограничивается оставшимся бюджетом; недостаточно
обрезать уже готовый вектор, потому что тогда KV/state уходят вперёд
невидимых пользователю токенов. Повтор после исправления: 21.5 ток/с и ровно
64 выданных токена.

Ранее маска строилась по числу попаданий эксперта в top-k. Для DeepSeek V4
это неверная величина: слабый восьмой маршрут и доминирующий первый получали
одинаковый голос. Теперь `CMF_MOE_STATS` накапливает нормализованный routing
weight каждого эксперта в fixed-point. При покрытии 92,5% это в среднем 40
экспертов на каждом из 40 learned-router слоёв (1599 всего); три hash-слоя
остаются полными.

Проверка aquarium-sidecar, калибровка только на первых 96 токенах:

| выборка | без маски | weighted 92,5% |
|---|---:|---:|
| первые 32 токена | 11.903 | **8.131** |
| 3 разнесённых окна × 32, stride 523 (93 scored) | 242.799 | **94.217** |

Высокий абсолютный PPL окон объясняется независимым сбросом контекста на
HTML/JS-фрагментах; для гейта важен парный результат на одних токенах.
Но даже хороший результат на коротком PPL-окне не доказал безопасность:
длинная autoregressive-генерация изменила prefix, затем маршруты разошлись и
качество разрушилось. Поэтому sidecar рядом с моделью больше не активируется.
Явный `CMF_MOE_MASK` сохранён только для исследований; публиковать или
выдавать его результат как результат исходной модели нельзя.

Speculation тоже выбирается без пользовательского флага, но обязана работать
поверх точного trunk. `CMF_DSV4_SPEC=1` остаётся диагностическим force, а
драфт может влиять только на скорость: каждый предложенный токен проверяет
исходная модель.

Физическая граница текущего A40: q4tp-файл занимает 158.5 ГБ, карта — 46 ГиБ,
измеренная полоса H2D — 8.3 ГБ/с. Один точный токен активирует примерно
5 ГБ expert-весов (8 routed + shared на 43 слоях). Поэтому 20 ток/с без
высокой cache-locality, принятого speculative блока или ограничения вселенной
экспертов на этом стенде недостижимы; число 20+ от hard-mask не считается,
пока held-out PPL не проходит гейт.

## Что именно взято у FreeToken и что сделано иначе

Изучены код и статья FreeToken, а не только README. Их центральный механизм:
единый global-LRU по парам `(layer, expert)`, точное разбиение каждого miss
между H2D и CPU по `q ≈ m·B_P/B_H`, параллельные ветви с exact partial merge
и double-buffer слоя при prefill. Опубликованные 22–25 ток/с относятся к
DeepSeek-V4 FP4 на RTX 5090, не к A40.

Текущий Vulkan/q4tp exact-путь теперь использует настоящий общий физический
pool. Из-за 4-ГиБ предела Vulkan он разбит на восемь descriptor-indexed
сегментов, но slot id и политика вытеснения едины для всей модели. В отличие
от чистого global-LRU, у каждого trunk-слоя есть защищённый минимум: общий
остаток свободно заимствуется горячими слоями, а последовательный обход не
может вымыть весь рабочий набор следующего токена. Точность обеспечивают
refill либо CPU-cold correction. Дополнительно CMF:

- GPU сам повторяет роутинг; ошибочный host prediction влияет только на
  скорость, не на ответ;
- cold expert даёт точную коррекцию из mmap вместо приближённого результата;
- один chain включает attention, router, subset MoE и hyper-connections;
- verify идёт батчем по пяти кандидатам MTP;
- q4tp не переквантуется в q2 на каждом старте;
- GPU-task-mask применяется до top-k, а masked-complete pack считается
  полноценным слоем.

## FCD для драфта

В текущем результате FCD не использован. Существующая команда `cortiq fcd`
восстанавливает плотные FFN после O(1)-аппроксимации и намеренно отклоняет
MoE-слои. DeepSeek V4 и его MTP-драфт — MoE, поэтому прямое включение этой
команды было бы неверным.

Правильный следующий вариант — отдельный `draft-fcd`:

1. q4 MTP служит учителем только для драфта;
2. собираются реальные MTP-активации и logits на калибровочном корпусе;
3. оптимизируются q2 scale-ladders экспертных gate/up и небольшой residual к
   Markov/head, а не trunk;
4. целевая функция — KL драфта к q4 MTP плюс survival-weighted loss первых
   пяти позиций;
5. арбитр — acceptance и tok/s на held-out; ответы trunk обязаны остаться
   токен-в-токен прежними.

Это особенно полезно q2tp: плохой драфт может только снизить скорость, но
никогда не меняет подтверждённый trunk-ответ. Для q4tp нативный MTP принял
57–62% предложений в последних 48–64-токенных прогонах, поэтому сначала
выгоднее сокращать стоимость batch verify и улучшать его калибровку.
