# q2tp: масштаб канала и уточнение кодов

Улучшенный рецепт 2-битной квантизации `q2tp`. Размер файла, формат и скорость инференса не меняются:
всё делается на этапе `cortiq quantize-gptq`. Измерено на MiniCPM5-2B 13.11.2026.

[English](Q2TP_SCALE_REFINE.md) · [中文版](Q2TP_SCALE_REFINE.zh.md)

## Принцип

Рецепт состоит из двух шагов поверх обычного GPTQ. Оба бесплатны по битам.

### 1. Масштаб канала, свёрнутый в нормализацию

У 2-битного кода один шаг на группу из 32 соседних входных каналов. Если веса каналов в группе сильно
различаются по величине, мелкие каналы теряются. Перед квантованием каждый входной канал `j` умножается
на свой множитель, а обратный множитель прячется в гейн RMSNorm перед слоем:

```
t_j = σ_j^0.75 / rms_j^0.25          σ_j  — RMS столбца j по всем строкам группы тензоров
                                     rms_j — RMS входа j на калибровке (√H_jj)
W' = W · diag(1/t)                   веса, которые идут в квантователь
γ' = γ ⊙ t                           гейн нормализации в выходном файле
H' = diag(t) · H · diag(t)           Hessian в новом базисе
```

`t` нормируется к единичному геометрическому среднему и ограничивается диапазоном `[1e-3, 1e3]`; у мёртвых
каналов `t = 1`. До квантования модель математически та же: `W'·(t⊙x) = W·x`.

Масштаб общий для тензоров, читающих один вход:

| Тензоры | Нормализация, в которую уходит `t` |
|---|---|
| `mlp.gate_proj` + `mlp.up_proj` | `post_attention_layernorm` |
| `self_attn.q_proj` + `k_proj` + `v_proj` (флаг `--channel-scale-qkv`) | `input_layernorm` |

Показатель степени существенен: при 0,5 выигрыш пропадает. При 1,0 (и ridge 1,0) результат был не хуже,
чем при 0,75: 26,72 против 26,99.

### 2. Уточнение кодов после GPTQ

GPTQ выбирает уровень для каждого веса один раз, слева направо. После него отдельные веса сдвигаются на
соседний уровень, если это уменьшает ошибку выхода слоя. Лестница масштабов и ступени групп не меняются.

```
r   = Ŵ_i − W_i                      остаток строки
H_f = H + 0.3 · mean(diag H) · I
g   = H_f · r
сдвиг веса j на Δ = ±s_группы меняет  r·H_f·rᵀ  на   2Δ·g_j + Δ²·H_f[j,j]
```

На каждом круге в строке применяется один самый выгодный сдвиг, затем `g += Δ·H_f[:, j]`. Кругов не больше
256; строка останавливается раньше, когда выгодных сдвигов нет. После уточнения идёт обычный debias
(сдвиг `lo` строки).

Ridge подобран: 0,1 и 0,3 дают одинаковый результат, 1,0 хуже, 3,0 вреднее, чем ничего.

## Команда

```bash
cortiq quantize-gptq MODEL.f16.cmf --codec q2tp \
  --calib CALIB.txt --calib-model MODEL.q8_2f.cmf \
  --tokens 32768 --window 2048 --lambda 0.01 \
  --tensor-quant lm_head.weight=q8_2f --tensor-quant model.embed_tokens.weight=q8_2f \
  --channel-scale 0.75 --channel-scale-qkv \
  --refine 256 --refine-ridge 0.3 \
  --output MODEL.q2tp.cmf
```

Остальное по умолчанию: лестница `placed`, debias включён. Токенов калибровки не меньше 32 768.

## Что проверить на новой модели

1. **Тождественность свёртки.** Тот же запуск с `CMF_CHSCALE_FP=1` пишет все линейные слои в f16 без
   квантования, со свёрнутым масштабом. Его перплексия должна совпасть с таким же запуском без
   `--channel-scale`. На MiniCPM5 это 16,903 и 16,902. Расхождение означает, что у архитектуры гейн
   нормализации устроен иначе (например `1 + γ`) или выход нормализации читает кто-то ещё.
2. **Число свёрток.** В логе по строке `channel scale <имя нормализации>` на каждую свёрнутую группу. Группа,
   не подошедшая по именам или составу, пропускается молча: слои GDN (`linear_attn.*`), эксперты MoE.
3. **Парное сравнение с базой** на тех же Hessian: тот же запуск без четырёх новых флагов. Смотреть
   перплексию модели, а не ошибку слоя: на 2 битах ошибка слоя не предсказывает перплексию.
4. **Текст вне калибровки и жадная генерация.**

## Ограничения

- Измерено на одной модели (MiniCPM5-2B, плотная Llama-подобная, GQA 16/2) и на WikiText-калибровке.
- Масштаб не применяется к входам `down_proj` и `o_proj`, к экспертам MoE и к слоям GDN.
- Группы, которых касаются новые флаги, сворачиваются и проходятся на CPU. Остальные группы остаются на
  карте, но этот смешанный путь на карте не запускался: на Mac всё идёт через CPU.
- При существующем кэше `--hessians` все группы идут через CPU.
- Точный подбор гейна по наименьшим квадратам (`--channel-refit`, гейн входного канала из кодировщика NVG) ничего не добавляет:
  −0,23 %. В рецепт не входит.
- Правило cortiq для слоя 7 (`--q2tp-rule-tensor`) в этом конвейере не помогает: −0,03 % ± 0,43.
- `--refine-q4tp` запускает то же уточнение на 16-уровневой сетке q4tp-тензоров; в этот рецепт не входит.

## Код и инструменты

`crates/cortiq-cli/src/gptq.rs`: `chscale_vector`, `chscale_norm_for`, `q2tp_refine_codes`,
`q4tp_refine_codes`, `channel_refit_gain`.

Перплексия q2tp/q4tp-файла на CPU считается медленно (около 18 ток/с на 2B-модели). `cortiq requant FILE
--quant tiled-q8_2f --output COPY` пишет q8_2f-копию, которая считается в 7 раз быстрее и завышает
перплексию на 0,4–0,7 % одинаково для всех вариантов.
