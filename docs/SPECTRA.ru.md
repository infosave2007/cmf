# Cortiq Spectra

`cortiq-spectra` — переносимая CPU-реализация потоковой раскраски
двухэнергетического рентгеновского захвата. Это детерминированный
физически мотивированный reference-процессор, а не обученная модель и не
медицинский диагностический прибор.

## Архитектура потока

Входной каталог содержит два энергетических потока и повторные строки
калибровки. Перед началом обработки повторные строки `gain_*` и `offset_*`
усредняются в четыре вектора детектора. Для каждой пары строк процессор:

1. нормирует high/low отсчёты с учётом gain/offset и защитой знаменателя;
2. вычисляет `-ln`-аттенюацию, отношение low/high, материал и уверенность;
3. отображает материал по детерминированной оси organic → mixed → metal и
   применяет ограниченный bilateral-like фильтр 3×3;
4. выдаёт строку после заполнения однорядного halo. На EOF крайние строки
   реплицируются, поэтому результат не зависит от границ chunk-а.

`StreamingColorizer` хранит только три соседние строки. Размер
`--chunk-rows` меняет расписание чтения, но не байты результата. API
`process_stream` и CLI материализуют все строки для записи PNG, поэтому сами
выходные буферы, естественно, имеют размер кадра; состояние потокового ядра
остаётся ограниченным halo.

## Безопасность и отказ от цвета

Недостоверные пиксели не получают правдоподобный цвет. Для каждого пикселя
сохраняется битовая маска отказа (флаги могут объединяться):

| Флаг | Причина |
|---|---|
| `1` (`REFUSAL_INVALID_CALIBRATION`) | gain/offset нечисловые или знаменатель `gain - offset` не превышает epsilon |
| `2` (`REFUSAL_SATURATED`) | исходный отсчёт равен `u16::MAX` |
| `4` (`REFUSAL_NONFINITE`) | нормированное значение не является конечным |

Любой ненулевой флаг передаётся в `StreamOutput.refusal`. Такой пиксель
получает чёрный RGB, нулевые material/confidence и исключается из фильтра и
из LUT. Политика `InvalidDenominator::Clip` допускает безопасное вычисление
промежуточного значения, но не снимает отказ. В `refusal.png` отказанные
пиксели белые, а доверенные чёрные, чтобы граница доверия была заметна при
обычном просмотре.

## Калибровочный профиль: fitting и runtime

Без reference-панели поток выдаёт физический baseline с палитрой из
`ColorParameters`. Если рядом с захватом есть
`reference/suitcase_colorized_declassify_bilateral_strong_rot.png`, CLI:

1. один раз считает baseline;
2. поворачивает reference из display-ориентации обратно в stream-порядок;
3. строит детерминированную RGB-LUT `128³`, используя только доверенные пары
   RGB/reference. Пустые bins заполняются средним доверенным RGB.

LUT — это профиль дисплея, не пространственная маска: в неё не входят
абсолютные координаты, object mask или состояние конкретного чемодана. При
runtime LUT применяется после row-фильтра только к доверенным пикселям.

`save_profile` записывает проверяемый CMF-контейнер:

- `scanner.profile`: F32-тензор формы `[4, width]` (gain/offset high/low);
- `scanner.color_lut`: необязательный U8-тензор формы `[size, size, size, 3]`;
- provenance `spectra.v1` с epsilon, политикой отказа и всеми
  `ColorParameters`.

`load_profile` проверяет границы и хэши CMF, схему provenance и конечность
значений, после чего возвращает готовый `Calibration`. Загруженный профиль
самодостаточен: результат не зависит от констант исходного кода. Для
проверки контейнера можно также выполнить `cortiq verify scanner-profile.cmf`.

## CLI

Ожидаются 16-битные одноканальные TIFF-файлы (имена фиксированы):

| Файл | Содержимое |
|---|---|
| `data_high.tif`, `data_low.tif` | энергетические потоки одинакового размера |
| `gain_high.tif`, `gain_low.tif` | повторные строки gain |
| `offset_high.tif`, `offset_low.tif` | повторные строки offset |
| `reference/suitcase_colorized_declassify_bilateral_strong_rot.png` | необязательная display-reference для fitting |

Запуск из корня репозитория:

```sh
cargo run --release -p cortiq-spectra -- \
  --input-dir /path/to/capture \
  --chunk-rows 64 \
  --out-dir artifacts/spectra/chunk-64-release
```

Флаги:

- `--input-dir` — каталог входных TIFF (по умолчанию заданный в бинарнике
  путь к захвату разработчика);
- `--chunk-rows N` — положительный размер chunk-а, по умолчанию `64`;
- `--out-dir DIR` — каталог результатов, по умолчанию
  `artifacts/spectra/chunk-N`.

CLI проверяет размеры энергий и калибровки, сохраняет профиль, загружает его
обратно с проверкой и только затем обрабатывает поток. В выбранном каталоге
появляются:

| Файл | Смысл |
|---|---|
| `rgb.png` | итоговый RGB в display-ориентации (поворот stream-кадра на 90°) |
| `material.png` | 8-битная шкала material |
| `confidence.png` | 8-битная шкала уверенности |
| `refusal.png` | белая маска отказанных пикселей |
| `scanner-profile.cmf` | CMF-профиль калибровки и, при fitting, LUT |
| `summary.json` | размеры, chunk, время, число отказов, confidence и MAE reference |

Для библиотечного runtime достаточно загрузить профиль и передать строки в
`process_stream`:

```rust,no_run
let calibration = cortiq_spectra::load_profile("scanner-profile.cmf")?;
let (rows, height) = cortiq_spectra::process_stream(
    calibration, &high, &low, 64,
)?;
assert_eq!(rows.len(), height);
```

## Измерения и границы применимости

Принятый захват имеет размер 576×3110 (3 110 строк), 71 530 отказанных
пикселей. Обработка ниже — release-запуски на одном и том же захвате; время
`processing` исключает декодирование TIFF, `wall` — полное время запуска:

| `chunk-rows` | processing, ms | wall, s |
|---:|---:|---:|
| 16 | 86.72 | 0.72 |
| 64 | 94.23 | 0.28 |
| 512 | 116.05 | 0.32 |

Для chunk 16/64/512 побайтно совпали `rgb.png`, все три серых PNG и
`scanner-profile.cmf`. RGB MAE относительно выданного reference равен
`28.3267515556151/255` (baseline без LUT — `33.47857568179111/255`). MAE —
средняя абсолютная ошибка трёх выровненных uint8-каналов; это не мера
материальной истины.

Полная картинка участвует в fitting, поэтому `28.33/255` — in-sample
метрика одного захвата. Отдельный spatial holdout (блоки 200×100, каждая
пятая полоса исключена из fitting) дал `30.732184250584318/255`; это
диагностика обобщения, а не независимая валидация нового сканера. LUT из
этого suitcase-захвата нельзя считать универсальной моделью: для нового
сканера нужен профиль, обученный на его representative reference-панелях.
