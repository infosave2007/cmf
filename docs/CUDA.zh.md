# CUDA 后端

*语言: [English](CUDA.md) · [Русский](CUDA.ru.md) · **中文***

cortiq 通过 wgpu（Vulkan、DX12、Metal）和自己的 Metal 路径在 GPU 上运行。在 NVIDIA 显卡上还有第三条路：
原生 CUDA 后端。它是实验性的，默认关闭：由构建 feature 打开，由环境变量选择。

```bash
cargo install cortiq-cli --features cuda      # 或在源码目录中：cargo build --release -p cortiq-cli --features cuda
CMF_GPU=cuda cortiq run spark-x2.6-4b-q4tp-turbo.cmf --prompt "..." --greedy --no-think
CMF_GPU=cuda cortiq bench spark-x2.6-4b-q4tp-turbo.cmf --ctx 4000 --tokens 60 --core
cortiq gpu        # 显卡和库是否就位
```

构建不需要 CUDA toolkit：不链接任何库。运行时后端打开驱动的 `libcuda` 和 toolkit 的两个库：`libnvrtc`
（编译内核）与 `libcublas`，版本 12.x。缺少其中任何一个时，`CMF_GPU=cuda` 在 CPU 上运行并说明原因
（`cortiq gpu` 或 `RUST_LOG=warn`）。

## 服务器

`cortiq serve` 在这个后端上与在其他后端上一样：OpenAI 兼容的 HTTP API，同一端口上还有网页面板。

```bash
CMF_GPU=cuda CMF_MAX_SEQ=131072 cortiq serve spark-x2.6-4b-q4tp-turbo.cmf --port 8080 --host 127.0.0.1
```

```bash
curl http://127.0.0.1:8080/v1/chat/completions -H "Content-Type: application/json" -d '{
  "model": "spark",
  "messages": [{"role": "user", "content": "Explain how a hash map works."}],
  "max_tokens": 256,
  "temperature": 0,
  "enable_thinking": false,
  "stream": true
}'
```

| 地址 | 作用 |
|---|---|
| `POST /v1/chat/completions` | 一轮对话；`stream: true` 边生成边返回，以 `data: [DONE]` 结束 |
| `POST /v1/completions` | 续写 `prompt` |
| `GET /v1/models` | 所服务的模型 |
| `GET /healthz` | 服务器运行时返回 200 |
| `GET /` | 网页面板 |
| `GET /v1/cortiq/status` | 引擎状态 |

- 请求里必须有 `model` 字段，名字任意：服务器只服务一个文件。
- `--host` 默认是 `0.0.0.0`，即所有网络接口，而且服务器不检查密钥；`--host 127.0.0.1` 让它只在本机可用。
- `CMF_MAX_SEQ` 是每个请求的上下文上限，默认 32 768。
- 接着上一个请求的新请求只读新增部分：共同开头的 K/V 行留在显卡上（20 个新词元 42 毫秒，87 个来自缓存）。
  超过 turbo 文件的封口之后，新一轮会把对话重新读一遍。
- `CMF_SERVE_SLOTS=N` 同时保留 N 个对话，各自的行都在显卡上：默认每四个 CPU 核一个，最多四个。它们的请求在
  显卡上轮流执行。两个请求同时发出，得到的文本与逐个发出时相同，速度为 38 和 64 tok/s，单个请求为 117。
- 每个请求结束后，服务器像 llama-server 一样打印耗时。A40 上一份 20 283 词元的文档，读入、封口并回答：

```
prompt eval time =    8334.96 ms / 20283 tokens (    0.41 ms per token,  2433.49 tokens per second)
       eval time =     710.31 ms /    63 tokens (   11.27 ms per token,    88.69 tokens per second)
      total time =    9045.26 ms / 20347 tokens
```

`scripts/cuda/pod/serve_turbo_check.sh` 在显卡上检查以上全部内容。

## 它能运行什么

带全局或滑动窗口注意力的稠密堆栈，即 Spark-X2.x 一类：q4tp、q8_2f 或 f32 权重，RMS 归一化，逐层的旋转
位置编码，Spark 的逐头输出门，SiLU 或 GELU 的 FFN。对它们，后端提供与 wgpu 相同的两个图接口：

- **解码**：所有层和输出头都在显卡上，隐藏行常驻，每个词元读回一次；
- **提示**：每块 1024 行通过所有层，K/V 行留在解码读取的镜像里；
- turbo 文件的**远场**：超过文件封口的提示先以精确注意力整段读完，之后封口一次；此后每个词元读取显卡上的
  远场状态，其代价和显卡内存不再随文本增长。`CMF_O1=off` 在任何长度都保持精确注意力。

Qwen3.5 系列的混合模型（`qwen3_5`：GDN 混合器与带门和 Q/K 归一化的全局注意力，稠密 FFN，一个 MTP
块；Qwen3.8-27B）走后端的第二条分支，草稿及其验证也都在显卡上，见[混合模型](#qwen35-系列混合模型)。
Fast Code 堆栈（`qwen4_exp`）有自己的路径（`gpu_cuda/qwen4.rs`）。其余的（其他 MoE、夹层归一化、这些之外的
输出门）在改动任何状态之前被拒绝，模型走 CPU 路径；`CMF_CUDA_DEBUG=1` 打印原因。

## 工作方式

Rust 一侧是 [cudarc](https://crates.io/crates/cudarc)：用于上下文、内存、模块加载和内核启动的 driver
API，以及 NVRTC 和 cuBLAS。内核用 CUDA C 写在 `crates/cortiq-engine/src/gpu_cuda/`，首次使用时按显卡
架构编译；解码注意力按模型的头几何编译。

**解码**把权重保留在其编码中，每个词元把每个矩阵读一次。一个内核 `mv_multi` 在一次启动中用同一输入行乘
多个矩阵（q、k、v 和头门；gate 和 up）。一个 warp 负责矩阵的一行；输入行每个块在共享内存中摆放一次，RMS
归一化和 q8_2f 的列场一并折入。该行按元素为主、以奇数步长存放，所以一个 warp 的 32 条通道读 32 个不同
的存储体。q4tp 一行的 32 个缩放值放在各通道的寄存器里，组的缩放是一次 warp 内 shuffle。注意力是 K/V
镜像上的三个小内核：分数（一个 warp 一行键，一行为 KV 组的四个查询头只读一次）、各块的指数与值的和、
对块求和并乘头门。

**提示**每块把每个权重展开成稠密的 f16 平面一次，用 cuBLAS 在张量核上相乘：操作数 f16，累加和输出 f32。
注意力是每层两次批量 GEMM（分数和值，四个 KV 组一次调用）夹着因果 softmax，按若干行一段，使分数矩阵保持
在约 384 MB。

**远场**（`nystrom.rs`）为封口后的层保留它精确读取的行（最前几行、选出保持精确的行、最后 1800 行的环），
放在与 K/V 镜像相同布局的缓冲区里，另有每个头在 32 个地标上的远场累加量：每层 18 MB。每个词元在精确注意力
的三次启动之外多两次：它要替换的环行并入远场累加量；该行注意力的远场部分作为又一块部分和输出，与近处各行
的内核留下的部分和共用同一个偏移。封口由主机完成：提示的 K/V 行和每八行取一行的查询从显卡读回，248 个
精确行在提示的全部行中选出。本后端在封口前读完整段提示，而 wgpu 路径在 8 192 行处封口，其余部分经远场
读取；`CMF_O1_WHOLE=1` 让 wgpu 路径按同样的顺序运行。

## 精度

解码在任何模式下都是 f32。提示由 `CMF_CUDA_PREC` 选择：

| 取值 | 权重 GEMM | 注意力 GEMM |
|---|---|---|
| `fast`（默认） | f16 操作数，f32 累加 | TF32 |
| `tf32` | TF32 | TF32 |
| `exact` | f32 | f32 |

`fast` 与 wgpu 路径矩阵单元内核同级。FFN 的中间量 `act(gate) · up` 除以 16 后转为 f16，GEMM 再乘回，因此
半精度能容纳到百万量级的数值。

## 一致性

参照是使用浮点激活的主机（`CMF_GPU=0 CMF_SDOT=0`）。四个提示，各解码 96 个词元，所有路径沿同一组 id
前进；与参照的最大 logit 差：

| 文件 | 路径 | top-1 与参照相同 | 首词元 | 其后的词元 |
|---|---|---:|---:|---:|
| q4tp | CUDA，`exact` | 384/384 | 0.0001 | 0.0002 |
| q4tp | **CUDA** | 384/384 | 0.020 | 0.016 |
| q4tp | Vulkan | 384/384 | 0.020 | 0.017 |
| q8_2f | CUDA，`exact` | 384/384 | 0.0001 | 0.0002 |
| q8_2f | **CUDA** | 384/384 | 0.019 | 0.023 |
| q8_2f | Vulkan | 384/384 | 0.014 | 0.015 |

精确注意力下的自由贪心运行，六个 20 到 20 255 词元的提示（最长的一个加 `CMF_O1=off`），各 96 个词元：每个
文件在 CUDA 和 Vulkan 上给出相同的 576 个 id。三轮对话，以及两次共享前缀的服务器请求（其 K/V 行被复用），在两条路径上文本相同。Vulkan 各行是 0.8.67 的：
提示之后的首词元走词元图的输出头，而 cortiq 0.8.66 对 q8_2f 文件用的是混合输出头（首词元相差 0.29）。

远场有三项检验。它的词元内核与 `NystromState::step_group` 在随机状态上对比，144 行、环转过一整圈：数值最大
2.3 时相差 3.5e-5（显卡上的单元测试）。从同一次封口（20 255 词元的提示）出发，显卡上的解码与主机上使用浮点
激活的解码对比，96 个词元：每一步 top-1 相同，logits 相差不超过 0.0002（q4tp）和 0.0004（q8_2f）。与按同样
顺序运行的 wgpu 路径对比，两边的提示都用 f32 读取：96/96、0.025（q4tp），95/96、0.50（q8_2f）。在默认精度下，
两条路径的远场更早分开，同一路径的两种精度也是如此：在这个提示上，wgpu 路径的默认精度与 f32 提示的 logits
平均相差 0.04（q4tp）和 0.65（q8_2f），CUDA 路径相同。封口会放大提示的舍入误差，精确注意力不会。埋在
60 000、120 000 和 240 000 字符维基百科文本中的事实，CUDA 上的远场 8 次全部答对
（`scripts/cuda/pod/chain_cuda_passkey.sh`）。

## Qwen3.5 系列混合模型

由 GDN 混合器和带门、带 Q/K 归一化的全局注意力组成的堆栈（`qwen3_5`，其中包括 Qwen3.8-27B）走自己的分支
`gpu_cuda/hyb.rs` 与 `hyb.cu`，接口仍是同样的两个图接口。流水线的草稿轮次、prompt lookup 和服务器在其上
无需改动即可运行。

```bash
CMF_GPU=cuda cortiq run qwen38-27b-q4tp.cmf --prompt "..." --greedy --no-think
CMF_GPU=cuda cortiq serve qwen38-27b-q4tp.cmf --port 8080 --host 127.0.0.1
```

**解码与验证**使用同一个张量核内核：`mma.sync` m16n8k16，操作数 bf16，求和 f32。
- 加载时显卡重排每个 q4tp 矩阵，使每个线程一次加载 16 行分块中属于自己的八个字节。
- 输入行以两个 bf16 平面进入内核，约 17 位有效数字，由算出这一行的内核写入。
- 至多十六行的代价与一行相近：在 3090 上八行为一行的 1.05 倍，十六行约 1.6 倍。
- 一行的运算与同一次启动中有多少行无关。因此验证窗口给出的正是普通词元的比特，带草稿的文本与不带草稿的
  文本相同。
- gate 与 up 合为一个矩阵，每个分块里各有八行。内核的收尾写出 silu(gate) · up，供 down 投影使用。

**GDN 与注意力**
- 一个 GDN 层是两次启动：卷积、其环形缓冲、L2 归一化和门在一次里，delta 规则在另一次里。
- 在 delta 规则中，一个线程负责 3 MB 状态的一列，因此一个 warp 读取 32 个相邻的数；验证时用于回退的状态
  副本由同一次启动写出。
- 注意力读取 f16 的 K/V 镜像。
- 一个词元或一个验证窗口是一个 CUDA 图，按其位置记录重放。
- 对长矩阵组的单行调用每个块取一个分块（gate/up 801 对 745 GB/s）；运算与此无关。

**草稿**
- 一轮的 MTP 草稿是一个 CUDA 图：每一步在显卡上取出其词元的嵌入行（嵌入的前 65 536 行，已重排），运行
  该块和短名单输出头，并在那里取 argmax。一次上传，一次启动，只取回 id。
- 验证在显卡上按主机的平局规则取每行的 argmax，logits 留在显卡上。
- 每轮带来两个及以上词元时，不先测普通词元就进行推测：在这一分支上一轮约等于 1.25 个普通词元。
- prompt lookup 延续与前文某段重复的草稿。其窗口为 8 行；某个 lookup 轮次的草稿全部被接受后为 16 行。
- 部分接受之后，每个 GDN 状态回到窗口起点并重放被接受的行：所有层共两次启动。

**提示**把重排后的权重展开为 f16 交给 cuBLAS，每块 1024 行。注意力在 f16 的 K/V 上运行，GDN 的衔接部分在
f32 内核中运行。

**加载**每个内核的 PTX 缓存在磁盘上（`~/.cache/cortiq/cuda`，`CMF_CUDA_CACHE`），重排在显卡上完成。27B
文件的计划在 4 秒内建好。

**聊天的下一轮**Qwen3.5 的模板在渲染之前的回答时去掉其思考块，因此下一轮从不延续已缓存的 id；循环状态也
无法回退。取而代之，读取提示时显卡在提示的最后一个 `<|im_start|>`（助手标题）处复制 GDN 状态，27B 文件约
150 MB。以其之前的 id 开头的一轮回到那里，只读取后面的内容。该点之前的注意力行是解码没有写过的提示行，
所以在任何草稿轮次之后这份副本都是精确的。草稿头在该点之前的行也会保留。`CMF_KV_REUSE=0` 让每一轮都从头
读取。

围绕一个 10 KB 文件的三轮对话（`scripts/q27cuda/serve_chat.sh`），每一轮都带着模型自己之前的回答：

| 轮次 | 提示，词元 | 重新读取 | **从快照继续** |
|---:|---:|---:|---:|
| 2 | 4 048 | 4 048 个，4.13 秒 | **338 个，0.50 秒** |
| 3 | 4 119 | 4 119 个，4.29 秒 | **78 个，0.24 秒** |

两种方式下三轮的文本都相同，解码速度也一样（第 2 轮 99 对 97 tok/s）。

### 文件旁的 DFlash 2

已发布的 DFlash 2 草稿器（`z-lab/Qwen3.8-27B-DFlash2`）一次前向写出一轮七个词元。它有五层，上下文是主干
第 5、19、33、47、61 层之后的行。在这一分支上，块在显卡上运行：
- 四位矩阵走同一个张量核矩阵向量乘；
- fc、卷积核投影和选择器在 cuBLAS 上以 f16 运行；
- 行卷积、头归一化和对上下文的注意力用各自的内核。

主干的图在途中把抽头行复制出来，草稿器的上下文在显卡上由它们构建。

```bash
hf download z-lab/Qwen3.8-27B-DFlash2 --local-dir dflash2
cortiq convert --model dflash2 --output qwen38-27b-q4tp.cmf --dflash-sidecar --quant q4tp   # 写出 qwen38-27b-q4tp.dflash.cmf
CMF_GPU=cuda CMF_DFLASH=1 cortiq run qwen38-27b-q4tp.cmf --prompt "..." --greedy --no-think
```

每一轮交给按这块显卡的价格能带来更多词元的草稿器。一个块约等于 0.19 个普通词元，验证八行为 1.24。
- 边车头部的路由器读取主干在末端的行。它按这些价格在记录下来的轮次上拟合（`cortiq dflash-route-fit …
  --prices`）。
- 没有路由器时，由测得的各草稿器接受率决定。
- 复制留给 MTP 链：尾部重复八个及以上词元，或 lookup 一直命中。来自词表高位部分的文本也一样。

## 选项

| 变量 | 含义 |
|---|---|
| `CMF_GPU=cuda` | 选择该后端（需以 `--features cuda` 构建） |
| `CMF_CUDA_DEVICE=N` | 显卡序号，默认 0 |
| `CMF_CUDA_PREC=fast\|tf32\|exact` | 提示的精度，见上 |
| `CMF_CUDA_BATCH=N` | 每块的提示行数，默认 1024 |
| `CMF_GPU_VRAM_MB=N` | 权重预算，代替显卡内存减 2 GB |
| `CMF_O1=off` | turbo 文件在任何长度都用精确注意力 |
| `CMF_CUDA_PROF=1` | 提示和词元各阶段的计时，每阶段后等待 |
| `CMF_CUDA_CACHE=DIR` | 编译后 PTX 的存放位置，默认 `~/.cache/cortiq/cuda` |
| `CMF_GRAPH_SPEC=0` | 不用草稿的混合模型 |
| `CMF_KV_REUSE=0` | 聊天的每一轮都从头读取 |
| `CMF_DFLASH=1` | 文件旁的 DFlash 边车为它赢得的轮次写草稿（`CMF_DFLASH_PICK=dflash\|mtp` 固定其中一个） |
| `CMF_CUDA_DEBUG=1` | 图被拒绝的原因，以及退出时的解码和提示汇总 |

## 限制

- 覆盖三类架构：Spark 类稠密堆栈（在 A40 上测量）、Qwen3.5 系列混合模型（在 RTX 3090 上测量）和 Fast Code
  堆栈。其他 MoE 和 Gemma 类堆栈在 `CMF_GPU=cuda` 下走 CPU，而不是 wgpu。
- 远场的提示是整段读取的：封口之前它的 K/V 行都在显卡上（64 000 词元时 8.2 GB，wgpu 路径为
  4.5 GB），所需时间比文本增长得更快。已封口对话的新一轮会把对话重新读一遍，wgpu 路径也是如此。
- 草稿在混合分支和 Fast Code 堆栈上运行，不在稠密分支上。turbo 文件封口之后，混合模型不用草稿解码。
- toolkit 的库必须在加载器的路径上；绑定针对 CUDA 12.x。
- 解码受自身运算限制：在 A40 上约 350 GB/s 的权重，而只加载权重的内核为 500
  （`scripts/cuda/bench/mv_bench.cu`）。

得出这些数据的运行：`scripts/cuda/`（pod 脚本、提示、内核基准）。
