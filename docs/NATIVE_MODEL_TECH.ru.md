# Нативная модель CMF (рабочее имя Cortiq-1) — технология

*Черновик технологии, 16 августа 2026. Основан только на том, что мы
измерили сами (эксперименты `cmf/experiments`, кампании Metal/5090,
патенты 10–17) — каждая цифра либо измерена, либо помечена как расчёт.*

## 0. Зачем и какой «вау»

Три сцены, которые модель должна показать «из коробки», без настроек:

1. **24 ГБ MacBook: 20B-параметров-класс модель отвечает 60–100 tok/s.**
   Файл ~8 ГБ, в памяти помещается вместе с системой и IDE. Секрет —
   не «быстрое железо», а байты на токен: активных параметров ~2.5B
   (мелкозернистые эксперты), четырёхбитная лестница q4tp с рождения,
   спекуляция на собственных MTP-головах (×1.7–2.5 на коде — измерено
   на Qwen3.8), голова словаря читается на 5%, а не на 100%.
2. **128k контекста в 300 МБ памяти и без потери скорости.** 7 из 8
   слоёв — наш O(1)-кор (постоянное состояние), 1 из 8 — точный якорь с
   компактным KV. Длинный документ не «тормозит и пухнет», как у
   softmax-моделей (Qwen3.8 на 32k теряет 30% скорости и 4 ГБ памяти,
   на 128k не влезает вовсе — расчёт из замеров 16.08).
3. **Один файл — много специалистов.** Скилы-накладки CMF (маски,
   FCD-хвосты) поверх одного backbone; смена специалиста — переключение
   маски, не второй файл. Модель обучена так, чтобы маски были честными
   (эксперты = крупные скилы, «router is coarse MoE»).

И четвёртая, инженерная: модель проектируется **под наш формат и рантайм**
(Metal/Vulkan/CPU/телефон уже есть), а не адаптируется к нему постфактум.

## 2. Архитектура

### 2.1 Схема слоя и стека

Стек из N блоков, шаблон **7+1**: семь блоков с O(1)-кором hybrid_k, восьмой —
**якорь** с точным вниманием. Каждый блок: `RMSNorm → микшер → +res →
RMSNorm → FFN → +res`; FFN — мелкозернистые эксперты (top-k + общий).

```
[hk][hk][hk][hk][hk][hk][hk][ANCHOR] × (N/8)      hk = hybrid_k O(1) core
                                                   ANCHOR = GQA softmax, o1-ready
```

Почему 7+1, а не 3+1 как у Qwen3.5: у Qwen 3+1 — доля softmax 25% и KV
растёт быстро; наш кор в опытах держит длинный контекст сам, а якорь нужен
для «точного адреса» (retrieval-головы, копирование, needle) — измеренные
76% retrieval-голов живут в немногих слоях. Финальный шаг (7+1 против 5+1
против 3+1) — абляция на Stage 0 при равном бюджете; 7+1 — гипотеза с
запасом по памяти (KV ÷ 8 относительно чисто-softmax).

### 2.2 Размеры (два тира)

| | Cortiq-1-Mini (proof) | Cortiq-1 (продукт) |
|---|---|---|
| слоёв | 24 (21 hk + 3 якоря) | 48 (42 hk + 6 якорей) |
| hidden | 1024 | 2560 |
| hybrid_k: голов × dv, nphase | 8 × 128, 32 фаз (стейт 8×64×128 = 64K чисел/слой) | 20 × 128, 32 фаз (стейт 20×64×128 = 164K/слой ≈ 0.65 МБ f32) |
| якорь | GQA 8q/2kv, hd 128, окно+sink+16 лендмарков | GQA 20q/4kv, hd 128, тот же режим |
| FFN | dense SwiGLU 2816 | 64 экспертов × inter 1024, top-4 + 1 общий (inter 4096) |
| параметры всего / активных | 0.4B / 0.4B | ~20B / ~2.4B |
| словарь | 64k, иерархический (256 кластеров × 256) | 128k, иерархический (512 × 256) |
| MTP | 2 draft-головы | 3 draft-головы |
| файл q4tp (эксперты q2tp) | 0.25 ГБ | ~7.5 ГБ (эксперты 2 бита) / ~11 ГБ (всё 4 бита) |

Арифметика токена продукта на M4 (расчёт из измеренных 100 ГБ/с и наших
ядер): активные байты ≈ 2.4B × 0.53 B ≈ 1.3 ГБ + голова 128k×2560 в
режиме shortlist ≈ 5% от 0.17 ГБ → **~14 мс/токен ≈ 55–70 tok/s plain**;
спекуляция на коде ×1.6–2 → **90–130 tok/s**; на 5090 — 250+ plain (упор в
фикс-косты, не в шину). Память состояния при 128k: hybrid_k 42 × 0.65 МБ +
якоря 6 × 128k × 4 kv × 128 × 2 × 2 Б (bf16) = **27 + 800 МБ**; в режиме
o1-ready у якорей — 27 + ~30 МБ.

### 2.3 Кор hybrid_k (наш «быстрый»)

Для головы h, признаков φ(θ) = [cos θ; sin θ] по nphase фазам:

```
θ_q = W_θq x,  θ_k = W_θk x,  v = W_v x,  κ = σ(W_κ x + b_κ), b_κ = +2
S_t = diag(γ) S_{t−1} + κ_t · φ(θ_k,t) ⊗ v_t        (γ — постоянный, лог-сетка горизонтов [8, 2L] по фазам/головам)
o_t = φ(θ_q,t)ᵀ S_t · norm(·) → W_o
```

- κ — единственная селективность (запись); decay без входа (измерено:
  вход-зависимый γ_t убивает обучение).
- Обучение — chunked gated scan (`vmf_chunked.py`, паритет 1.8e-5): интра-чанк
  через матрицу γ^{i−s}, интер-чанк — рекуррентно; **C = 32, C·MAX_DECAY ≤ 16**
  (правило NaN-безопасности), bf16 с f32-аккумулятором стейта.
- Инференс — уже в рантайме (`vmf_phase`, κ-гейт `vmf_attn.k_gate`), O(1)/токен,
  на Metal — тот же ряд ядер, что у GDN (регистровая рекуррентность на b
  позиций для verify-графа пишется по образцу `gdn_state_b`).
- Численность: признаки в [−1,1] → 4-битная лестница на W_θq/W_θk безопасна.

### 2.4 Якорь: точное внимание, «o1-ready»

Хвосты softmax тяжёлые (§1) — якорь хранит полный KV, но их 1 из 8 и KV
компактный (bf16, hd 128, 4 kv-головы). Плюс режим **o1-ready**, обучаемый:
внимание = sink (4 токена) + точное окно W=128 + m=16 лендмарков (K̃, Q̃, M_u
по патенту 16), лендмарки **пересчитываются каждые R=256 позиций внутри
обучения** (reseal — часть forward'а, не постфактум). Тогда потоковый режим
O(1) — не приближение чужой модели, а то, чему модель училась: дрейфа нет
по построению. На инференсе пользователь выбирает: полный KV (максимум
качества, 800 МБ на 128k) или o1 (30 МБ). Оба режима — одни веса.

### 2.5 Голова словаря: иерархическая, exact-margin

Словарь 128k разбит на 512 кластеров × 256 (кластеры формируются по
эмбеддингам токенов, переобучаются каждые N шагов): логит = логит кластера
+ логит внутри кластера (два матвека 2560×512 и 2560×256). Декод: exact-margin
(границы через центроид+радиус, у нас есть математика и точный вариант для
greedy; для сэмплинга — точный top-k с сертифицированным хвостом). Плюс
регуляризатор на обучении, сжимающий радиусы кластеров → границы тугие →
читаем ~5% строк. Экономия: 29% токена у 0.8B-класса → ~5%.

### 2.6 MTP и спекуляция

Три независимых draft-головы (лёгкие блоки на общем hidden, как у Qwen —
но не цепочка одного блока, а t+2, t+3, t+4 из одного состояния), обучаются
совместно с основной потерей (вес 0.3). Инференс — наш verify-граф:
b-row проверка одним сабмитом (веса читаются раз на b токенов), replay-коммит
рекуррентных состояний (hybrid_k — как GDN сегодня), shortlist-голова для
черновика. Ожидание по измеренному на Qwen3.8: приём ≥ 3–4 из 4 на коде →
×1.7–2.5.

### 2.7 Квант с рождения

QAT на последних 10–15% обучения к целевым сеткам: q4tp-лестница (лог-шаг
масштабов по строкам — наш формат) для всего, кроме экспертов; эксперты —
q2tp (измерено: эксперты переживают 2 бита). Файл продукта: ~7.5 ГБ. Норма-
слои, κ, θ-проекции — f16.

## 3. Обучение

### 3.1 Данные и токенизатор
Смесь: веб (fineweb-edu класс) 55%, код 25%, математика/рассуждения 10%,
многоязычие (ru/zh/de/…) 10%; длинные документы для контекст-курса; чат-
данные на SFT-этапе с явным контрактом инструментов (по умолчанию —
отвечать; tool-call только при объявленных tools). Токенизатор 128k BPE
(свой или переиспользованный) — с иерархией кластеров, построенной по
частотам/эмбеддингам.

### 3.3 Инфраструктура
torch + Triton-ядро chunked scan (наша факторизация), FSDP; паритет-оракулы
из репо (Rust ≡ torch 2e-7 для vmf_phase уже есть); экспорт в CMF
конвертером с дескрипторами слоёв (`vmf_phase`, якорь `full`, эксперты
`moe`), скилы — как сегодня.

## 4. Оценка и гейты
- S0: ppl wikitext/fineweb-val против двойника при равном бюджете (гейт:
  ≤ +10%), needle-in-haystack 32k/128k (гейт: ≥ 95% при 8k-обучении +
  экстраполяция), длинная генерация без петель (аквариум-спек, наш гейт
  FCD), приём MTP на коде ≥ 3/4.
- Скорость: `cortiq bench --core` на M4/5090/телефоне (наши стенды), TTFT
  через префилл-граф.
- Численность: оракулы verify/commit/attend (уже в рантайме).

## 5. Деплой
Один `.cmf`: дескрипторы слоёв, q4tp/q2tp планы, MTP-головы, иерархия
головы (тензоры `head.cluster.*`), скил-накладки. Платформы: Metal
(whole-token/verify/prefill-графы), Vulkan/DX12, CPU (SDOT/AMX), телефон
(client в сетевом сплите), сервер OpenAI-API. Спекуляция и o1-режим — флаги
рантайма, не разные файлы.

## 7. Риски (что убивает проект)
1. hybrid_k при равном бюджете хуже softmax больше чем на 10% на 0.4B — тогда
   тир продукта переезжает на 3+1 и/или GDN-микшер (наш рантайм держит оба).
2. Мелкозернистые эксперты на Metal: наш MoE-путь измерен ~7–18 tok/s на
   35B-A3B (не у полосы) — нужен профиль ядер `q4tp_matvec_jobs` под 64
   экспертов до S1.
3. Бюджет S1 — единственный настоящий барьер; S1' (upcycling) — план Б.
4. Токенизатор/иерархия: плохие кластеры = широкие радиусы = нет экономии на
   голове (лечится регуляризатором, измеряется на S0).
5. Поведение (tool-call, think): решается данными SFT и контрактом шаблона.

## 8. План работ (первые 6 недель)
1. Неделя 1–2: репо обучения (torch/Triton hybrid_k, якорь o1-ready,
