# Cortiq Decision на Metal

Доступно начиная с Cortiq 0.8.0. Тот же CMF-файл, без переобучения и конвертации.

## Запуск на Apple Silicon

```bash
cargo install cortiq-cli --locked
CORTIQ_DECISION_DEVICE=metal cortiq decide \
  /path/to/cortiq-decision.cmf --skill banking77 \
  -p "I still have not received my new card"
```

Для сервера применяется тот же выбор устройства:

```bash
CORTIQ_DECISION_DEVICE=metal cortiq serve \
  /path/to/cortiq-decision.cmf --host 127.0.0.1 --port 8091 \
  --state ./decision-metal-state
```

`GET /healthz` показывает `encoder_device` и счётчики реально завершённых
`metal_encoder_submissions` / `metal_resonance_submissions`.

`CORTIQ_DECISION_DEVICE=cpu` или отсутствие переменной сохраняют прежний CPU-путь.
Нужен Rust 1.88 или новее. Для Linux GPU есть отдельный
[Vulkan-путь](VULKAN_RU.md).

## Что ускорено

Решение по-прежнему определяется **ошибкой реконструкции**, а не генерацией ответа.
Metal ускоряет и подготовку признаков текста, и сравнение с топологиями навыков:

- Один command buffer на запрос: BERT → усреднение и два L2-прохода → ошибки
  реконструкции всех запрошенных локальных навыков. Между этими этапами нет
  чтения на CPU и повторного ожидания GPU.
- Веса постоянно находятся в Metal-буферах. Выровненные матрицы читаются
  SIMD-группами напрямую, без промежуточного копирования каждого блока.
- Нормализация небольших скрытых состояний удерживает значения в регистрах.
- Реконструкция сохраняет последовательное обновление остатка по векторам
  базиса — в том числе для неортогональных базисов. Уменьшенная точность,
  переобучение и предположение об ортогональности не используются.
- На CPU остаются токенизация, хеш-признаки, ранжирование, пороги уверенности
  и работа с оракулом. Оракул не участвует в локальном benchmark.

Формат и байты `.cmf` не меняются. Вычисления FP32, fast math выключен.
GPU-редукции меняют порядок сложения: значения не обещаются побитово равными
CPU. Порог контрольных эмбеддингов остаётся `1e-5`; решения и отказы
проверяются отдельно. CPU-путь сохраняет исходные вычисления.

Одинаковый совместный путь используется CLI, `/v1/decisions`, `/v1/route` и
benchmark. Параллельные запросы защищены mutex; навыки блокируются в едином
порядке, даже если разные энкодеры запрашивают их в обратном порядке.
Ошибка GPU не маскируется переходом на CPU.

### Честные тайминги

`timings_us.gpu` — общее время совместного GPU-прохода, включая ожидание.
Его нельзя выдавать за два независимых измерения энкодера и реконструкции.
В этом режиме `encode=0`, а `resonance` содержит только последующее CPU-ранжирование.
На CPU прежние поля сохраняют свой смысл; поле `gpu` не добавляется в JSON.
В совместимом `/v1/route` общий GPU-проход включён в `meta.latency_ms` и отдельно
показан в `meta.gpu_pipeline_latency_ms`; `embedding_latency_ms` содержит
оставшуюся подготовку на CPU. Один и тот же GPU-проход не считается дважды.

## Ограничения

Metal пока включается явно. Скорость зависит от длины текста, количества
топологий и нагрузки на общий GPU. Копии весов на GPU требуют дополнительной
памяти: ускорение не означает снижение RAM. Батчевый throughput и энергопотребление
этой проверкой не измеряются.

## Воспроизводимая проверка

```bash
cargo test --release -p cortiq-decision
cargo test --release -p cortiq-decision \
  --test encoder_metal --test resonance_metal --test pipeline_metal -- --ignored
cargo run --release -p cortiq-decision --example metal_compare -- \
  /path/to/cortiq-decision.cmf /path/to/test.jsonl banking77
```

JSONL содержит `{"text":"...","label":"..."}`. Метка необязательна для проверки
совпадения двух путей. Benchmark выполняет 50 прогревов; дальше поочерёдно
меняет порядок CPU/Metal для каждого запроса. Сравнивает эмбеддинги, ошибки,
победителя и отказ; считает реально завершённые GPU-команды. В измерение
входит полный локальный путь от текста до решения, но не загрузка модели,
компиляция шейдеров, сеть или оракул. Скрипт завершается ошибкой при различии
решений/отказов либо превышении допуска эмбеддингов или реконструкции
(`|E_GPU−E_CPU| / (1+|E_CPU|) ≤ 2e-5`).
