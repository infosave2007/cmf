# Nemotron-Labs Dory на cortiq

*Языки: [English](DORY.md) · **Русский** · [中文](DORY.zh.md)*

[Dory 1.0 4B](https://huggingface.co/nvidia/NVIDIA-Nemotron-Labs-Dory1.0-4B-BF16) — циклический трансформер
NVIDIA: 16 входных подслоёв, 40 рекуррентных и 16 выходных, 4 млрд параметров. Рекуррентный блок проходит
несколько раз по одним и тем же весам, поэтому один чекпоинт работает с 1, 2 или 4 циклами без дообучения.
Модель рассуждает в `<think>` и вызывает инструменты.

## Запуск

```bash
cargo install cortiq-cli
hf download infosave/Nemotron-Labs-Dory1.0-4B-cmf dory-turbo.cmf --local-dir .
cortiq run dory-turbo.cmf --prompt "Напиши функцию на Rust, которая разворачивает список." --no-think
```

На карте NVIDIA — бэкенд CUDA ([docs/CUDA.ru.md](CUDA.ru.md#dory-зацикленный-ngpt)):

```bash
cargo install cortiq-cli --features cuda
CMF_GPU=cuda cortiq run dory-turbo.cmf --prompt "Напиши функцию на Rust, которая разворачивает список." --no-think
```

| файл | веса | размер | ppl на wikitext-2 | назначение |
|---|---|---:|---:|---|
| `dory-turbo.cmf` | 4 бита, GPTQ | 2,09 ГБ | 14,22 | те же веса, что в `q4tp-v2`, плюс роутер и дальнее поле; **по умолчанию** |
| `dory-q4tp-v2.cmf` | 4 бита, GPTQ | 2,09 ГБ | 13,96 | два цикла на каждом токене |
| `dory-q8_2f.cmf` | 8 бит | 4,01 ГБ | 13,44 | ближе всего к оригиналу |

Перплексия: двенадцать окон по 512 токенов из wikitext-2 test, по одному токену. Оригинал bf16 даёт на них
13,42.

## Сервер

`cortiq serve` отдаёт файл через HTTP API, совместимый с OpenAI, а на том же порту — веб-панель:

```bash
cortiq serve dory-turbo.cmf --port 8080 --host 127.0.0.1
# на карте NVIDIA через CUDA, с запасом под длинные документы
CMF_GPU=cuda CMF_MAX_SEQ=131072 cortiq serve dory-turbo.cmf --port 8080 --host 127.0.0.1
```

```bash
curl http://127.0.0.1:8080/v1/chat/completions -H "Content-Type: application/json" -d '{
  "model": "dory",
  "messages": [{"role": "user", "content": "Напиши функцию на Rust, которая разворачивает список."}],
  "max_tokens": 512,
  "temperature": 0,
  "enable_thinking": false,
  "stream": true
}'
```

Подойдёт любой клиент OpenAI с `base_url="http://127.0.0.1:8080/v1"` и любым ключом API:

```python
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:8080/v1", api_key="none")
r = client.chat.completions.create(
    model="dory",
    messages=[{"role": "user", "content": open("report.txt").read() + "\n\nПерескажи это."}],
    temperature=0,
    extra_body={"enable_thinking": False},
)
print(r.choices[0].message.content)
```

| адрес | что делает |
|---|---|
| `POST /v1/chat/completions` | реплика чата; `stream: true` отдаёт ответ по мере декода, `tools` даёт модели вызывать функции |
| `POST /v1/completions` | продолжение `prompt` |
| `GET /v1/models` | отдаваемая модель |
| `GET /healthz` | 200, пока сервер работает |
| `GET /` | веб-панель |

- `model` может быть любым именем: сервер отдаёт один файл. `"enable_thinking": false` просит прямой ответ,
  как `--no-think`; без него модель сначала рассуждает, так что дайте ей больше `max_tokens`.
- `--host 127.0.0.1` оставляет сервер локальным. По умолчанию `0.0.0.0` — все интерфейсы, и ключи не
  проверяются.
- `CMF_MAX_SEQ` — потолок контекста запроса, по умолчанию 32 768. Длинный документ читается по-турбо, и
  память карты не растёт: на RTX 2000 Ada (16 ГБ) через CUDA 60 000 символов (15 277 токенов) прочитаны за
  8,3–9,4 с, ответ — 79 ток/с, карта не выше 3,77 ГБ (через Vulkan 66 с и 55 ток/с).
- `CMF_SERVE_SLOTS=N` держит N разговоров сразу, у каждого свои строки на карте. `CMF_O1_SPILL=DIR` держит
  строки длинного промпта, пока он читается, в файлах, а не в RAM.
- Запрос, продолжающий предыдущий, читает только новое. Новая реплика разговора за печатью читает разговор
  заново.

Подробнее — в [docs/CUDA.ru.md](CUDA.ru.md#сервер).

## Режимы циклов

| флаг | смысл |
|---|---|
| `--loops N` | постоянное число циклов, от 1 до 16; на турбо-файле заодно выключает роутер, дальнее поле и остальное |
| `--loops auto` | один или два прохода на токен: роутер файла, а в файле без него — верхняя вероятность |
| `--kv-cache per_loop\|last_loop` | свой кеш на цикл или один на все |
| `--o1 m,w,sink` | дальнее поле на слоях полного внимания, запечатка с 8192 строк |
| `--full-window N` | вместо этого обрезать слои полного внимания до окна |
| `--o1-spill DIR` | строки длинного промпта в файлах в `DIR`, также `CMF_O1_SPILL` |

`CMF_DORY_O1=m,w,sink,seal` задаёт и позицию запечатки, `CMF_DORY_O1=off` выключает дальнее поле турбо-файла.
`CMF_DORY_GATE=conf:0.7` или `recon:FILE:bias` выбирает гейт. `CMF_DORY_PROMPT_LOOPS=N` задаёт проходы по
промпту, `CMF_DORY_EXACT=FILE:rows` — отбор точных строк, `CMF_DORY_EXACT_LOG=FILE` пишет оценку каждой строки.

## Что делает турбо-файл

Турбо-файл хранит те же веса, а заголовок включает пять вещей.

![Один проход или два](https://huggingface.co/infosave/Nemotron-Labs-Dory1.0-4B-cmf/resolve/main/assets/router_ru.png)

**Кеш последнего цикла.** Каждый рекуррентный слой внимания держит один кеш, и каждый проход перезаписывает
строку этого токена. Число циклов может меняться от токена к токену, дыр не остаётся.

**Резонансный роутер.** После первого прохода состояние восстанавливают два изолированных подпространства PCA
ранга 16, построенные на токенах, где второй проход изменил ответ, и на токенах, где не изменил. Меньшая ошибка
решает, выйдет ли токен из цикла. Обучения градиентом нет, а решение не требует прохода через выходной блок и
голову. Примерно 85 % токенов идут за один проход.

**Дальнее поле.** Слои полного внимания держат точно первые строки и последние 1536, а всё остальное сводят к
32 опорным точкам на голову (`nystrom`). Скользящие слои и так держат окно в 1024 строки. Память на устройстве
перестаёт расти, и цена токена тоже. Так и при чтении промпта: после 8192 строк строки каждого куска уходят с карты,
как только он прочитан, в RAM или в файлы, пока дальнее поле не соберётся по ним заново.

| промпт, токенов | пик на карте | RAM | с `--o1-spill`: RAM | с `--o1-spill`: диск |
|---:|---:|---:|---:|---:|
| 1 000 | 3,08 ГБ | 0,2 ГБ | | |
| 12 000 | 3,76 ГБ | 1,4 ГБ | 1,2 ГБ | 2,0 ГБ |
| 32 000 | 3,76 ГБ | 3,6 ГБ | | |
| 64 000 | 3,76 ГБ | 7,2 ГБ | 1,7 ГБ | 9,6 ГБ |

RTX 5090, Vulkan, диск с записью 4,2 ГБ/с. Веса занимают из этого 1,95 ГБ, скорость в RAM и в файлах одна и та же, а файлы
удаляются, когда дальнее поле собрано. На MacBook Air M4 при 23 000 токенов пик footprint 3,27 ГБ, с `--o1-spill` 1,64 ГБ.
На CUDA RTX 2000 Ada держит 3,8 ГБ от 16 000 до 64 000 токенов (cortiq 0.8.72 или новее; 0.8.71 читал промпт
целиком и доходил до 7,5 ГБ на 64 000), см. [docs/CUDA.ru.md](CUDA.ru.md#dory-на-карте-16-гб).

![Что длинный промпт хранит на карте](https://huggingface.co/infosave/Nemotron-Labs-Dory1.0-4B-cmf/resolve/main/assets/far_field_ru.png)

**Точные строки.** Одно дальнее поле теряет пароль: точная модель находит его в 100 000 символов текста, а
дальнее поле нет. Поэтому строки, которые оно потеряло бы, остаются точными. На каждую KV-голову каждого полного
слоя считаются два числа для строки: насколько ключ лежит вне пространства опорных точек и норма значения. Каждое
превращается в ранг внутри промпта, а линейная модель по 72 рангам даёт оценку строки. Перед последними 512
строками промпта 512 лучших строк с соседями уходят из дальнего поля, а оно собирается заново уже без них. Порядок
важен: вопрос несёт найденное в тексте дальше к ответу, поэтому сам должен прочитать точный факт. Строки пароля
занимают первые места среди десятков тысяч строк.

![Как пароли остаются точными](https://huggingface.co/infosave/Nemotron-Labs-Dory1.0-4B-cmf/resolve/main/assets/exact_rows_ru.png)

**Промпт за один проход.** При кеше последнего цикла от строки промпта остаются только строки кеша, а логиты
никто не читает. Все куски, кроме последнего, идут за один проход, что стоит 1 % перплексии дальнейшего текста.

## Как собрать турбо-файл

Роутер строится по ответам самой модели. Скрипты лежат в `scripts/dory/router`, аргументы указаны в первых
строках каждого:

| скрипт | что делает |
|---|---|
| `gen_samples.py` | ответы модели на смешанный набор запросов |
| `loop_probe.py` | при подстановке ответа: логиты 1, 2 и 4 циклов и состояние после прохода |
| `router_fit.py` | две топологии на половине ответов, AUC на другой половине |
| `make_bin.py` | топологии плоским файлом и порог для нескольких долей токенов за один проход |
| `illum_feat.py` | промпты с посаженным фактом, остатки и нормы значений каждой строки |
| `illum_budget.py` | подбор весов, покрытие на невиданных промптах, веса для файла |

```bash
cortiq dory-turbo dory-q4tp-v2.cmf dory-turbo.cmf --topologies phi1.bin --bias -0.000258 \
    --o1 32,1536,4,8192 --exact-weights keep.bin --exact-rows 512
```

Более высокий порог оставляет больше токенов на двух проходах. Окно, стоки и точные строки в сумме до 2052
оставляют запечатанные куски промпта на пакетных ядрах; выше они идут построчно.

**Что остаётся за рамками.** Строки, пришедшие после конца промпта, могут быть только в окне или в дальнем поле.
Реплика, расходящаяся с запечатанным разговором, читает весь промпт заново и выбирает снова.

## Конвертация

```bash
hf download nvidia/NVIDIA-Nemotron-Labs-Dory1.0-4B-BF16 --local-dir bf16
cortiq convert --model bf16 --quant f16 --output dory-f16.cmf --also-output q8_2f=dory-q8_2f.cmf
cortiq quantize-gptq dory-f16.cmf --codec q4tp --calib-model dory-q8_2f.cmf \
    --calib wiki_train.txt=0.6 --calib data_chat.txt=0.25 --calib data_code.txt=0.15 \
    --tokens 32768 --window 2048 --lambda 0.01 --output dory-q4tp-v2.cmf
```

В `scripts/dory/` лежат эталон, скрипты паритета и замеров, а в `JOURNAL_DORY_2026-11-04.md` — журнал того, что
пробовали.

## Паритет

Жадный текст на сыром промпте совпадает с эталоном f32. Против vLLM на весах NVIDIA: 64 токена из 64, наибольшая
разница логарифма вероятности 3e-4, включая промпт из 1500 токенов. q4tp на Vulkan против CPU: 8,9e-4; Metal
против CPU: 7,7e-3. Ядра внимания сохраняют перплексию до трёх знаков на Vulkan и Metal.
