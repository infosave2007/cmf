# Qwen3.8-27B Turbo на cortiq

*Языки: [English](QWEN38_TURBO.md) · **Русский** · [中文](QWEN38_TURBO.zh.md)*

[Турбо-файл](https://huggingface.co/infosave/Qwen3.8-27B-Turbo-cmf) содержит 4-битные веса Qwen3.8-27B с
заголовком, который держит память карты на месте при длинных промптах. Промпты короче 8192 токенов идут с точным
вниманием, как в [обычном файле](https://huggingface.co/infosave/Qwen3.8-27B-cmf).

## Запуск

```bash
cargo install cortiq-cli
hf download infosave/Qwen3.8-27B-Turbo-cmf qwen38-27b-turbo.cmf --local-dir .
cortiq run qwen38-27b-turbo.cmf --prompt-file report.txt --greedy --no-think
cortiq run qwen38-27b-turbo.cmf --prompt-file report.txt --greedy --no-think --o1-spill /mnt/ssd/cortiq
```

| параметр | значение |
|---|---|
| `--o1-spill DIR` | строки длинного промпта в файлах в `DIR`, также `CMF_O1_SPILL` |
| `--prompt-file FILE` | промпт длиннее, чем вмещает командная строка |
| `CMF_O1_PREFIX_MAX=N` | запечатать на `N` строках, а не по размеру карты |
| `CMF_O1=off` | обычная модель, точное внимание при любой длине |
| `CMF_O1_SPEC=0` | без черновиков над дальним полем |
| `CMF_O1_STAGES=0` | внимание дальнего поля одним длинным потоком на голову |
| `CMF_WGPU_BLOCK_MB=N` | блок, который аллокатор Vulkan делит между малыми буферами, по умолчанию 16 МиБ |

## Что происходит с длинным промптом

![Длинный промпт на маленькой карте](https://huggingface.co/infosave/Qwen3.8-27B-Turbo-cmf/resolve/main/assets/ceiling_ru.png)

1. Первые строки читаются точно на пакетном графе: 8192 строки или 4096, если в бюджете карты нет места на большее
   (`o1_seal_for_card`).
2. Следующие куски читают дальнее поле, собранное по уже прочитанным строкам. Их запросы, ключи и значения уходят с
   карты через буфер, видимый хосту, в RAM или файлы (`O1Archive`).
3. Перед последними 512 строками среди всех сохранённых строк выбираются точные, а дальнее поле строится из строк
   заново, слой за слоем, поэтому в памяти никогда не лежат строки двух слоёв сразу.
4. Последние строки и каждый токен декода читают стоки, точные строки, окно из 1800 строк и 32 опорные точки на голову.
   Размер состояния постоянный.

Порядок на шаге 3 важен: вопрос несёт найденное в тексте к ответу, поэтому точный факт он должен прочитать сам. Если
выбирать после строк вопроса, строки факта находятся, но верный ответ выходит только в 1 случае из 8.

**Точные строки.** На каждую KV-голову каждого полного слоя два числа на строку: насколько ключ далёк от пространства
опорных точек и норма значения. Каждое становится рангом внутри промпта, и линейная модель по 128 рангам даёт строке
оценку. Списков слов нет. На вставленных фактах строки факта в среднем попадают в верхние 0,22 % промпта, в худшем случае
в верхние 0,96 %, на промптах, которых модель не видела.

**Короткие потоки.** Рабочая группа остаётся на одном SM карты NVIDIA, поэтому одна группа на 256 потоков на голову
оставляет карту без дела. `o1_stages` разбирает арифметику на части: близкие оценки с потоком на ключ, оценки опорных
точек, наибольшая оценка, дальняя часть на голову, веса, сумма значений кусками и сложение кусков. Запечатанный токен
ускорился с 31,5 до 56 ток/с, а проверка пяти строк с 57 до 41 мс.

**Черновики.** Пакет проверки читает внимание, не сдвигая дальнее поле, а его ключи и значения ждут на карте. Затем
`o1_spec_commit` сдвигает состояние только на принятые строки. Голова черновиков разогревается на последних строках
промпта. Текст при жадном декодировании с черновиками и без них один и тот же.

**Память карты.** Веса от 33 до 64 МиБ занимали по целому блоку в 64 МиБ, поэтому 12,6 ГБ весов держали 16,6 ГБ карты.
Блоки по 16 МиБ возвращают это место всем моделям на Vulkan при той же скорости.

## На Маке

M4 читает 13,6 ГБ весов, нужных на токен, со скоростью 92–95 ГБ/с, это скорость его памяти: 6,4 ток/с без черновиков.
Остальное дают два переключателя, оба по умолчанию выключены.

**Черновики**, `CMF_GRAPH_SPEC=1`. Черновая голова предлагает токены, один проход по весам их проверяет, и проход
даёт больше одного токена. MacBook Air M4, жадный декод, 220 токенов, текст с черновиками и без них один и тот же:

| ответ | без черновиков, ток/с | с черновиками, ток/с |
|---|---:|---:|
| эссе | 6,4 | **10,1** |
| объяснение на русском | 6,4 | **10,7** |
| функция на Rust с тестами | 6,4 | **12,1** |
| цитаты из промпта | 6,4 | **15,0** |
| правка кода из промпта | 6,4 | **20,5** |

После промпта в 3 600 токенов: 6,0 → 8,3 ток/с. Это дают три вещи. Проверка двух или трёх строк идёт пакетным
матвеком, который читает веса так же быстро, как одна строка: 95,7 и 82,4 ГБ/с против 60–67 у GEMM, и его логиты
совпадают с обычным путём до четвёртого знака. Глубина цепочки следует тому, как часто держится каждый её черновик:
на большинстве текстов это два черновика, а фиксированные семь на эссе не давали ничего. Там, где ответ повторяет
отрезок промпта или самого себя, цепочку до семи черновиков продолжают токены, которые шли за этим отрезком
(`CMF_SPEC_LOOKUP=0` это выключает). За печатью, на 16 000 токенов, черновики до этих изменений давали 4,6 ток/с
против 4,9, заново это не измерялось.

**Neural Engine**, `CMF_ANE=1`. Он читает чанки промпта рядом с GPU: FFN каждого слоя, проекцию `z` GDN-миксера и `q`
слоя внимания. Первый токен на 3 600 токенов 73,9 → 28,3 с, текст тот же; на 10 000 токенов с `--o1-spill`
217,6 → 113,5 с при пике памяти процесса 3,4 ГБ. Декод остаётся на GPU.

Таблицу считает `scripts/dory/q27_spec_decode.sh`; журналы в `JOURNAL_Q27_MAC_DECODE_2026-11-06.md` и
`JOURNAL_Q27_ANE_2026-11-05.md`.

## Как собрать турбо-файл

```bash
python3 scripts/dory/router/q27_feat.py cortiq qwen38-27b-q4tp.cmf tokenizer.json wiki_test.txt keep27.bin
cortiq far-turbo qwen38-27b-q4tp.cmf qwen38-27b-turbo.cmf --exact-weights keep27.bin
```

В `scripts/dory/router/keep27.bin` лежит модель для Qwen3.8-27B. `--o1 m,w,sink`, `--seal` и `--exact-rows` задают поле;
окно, стоки и точные строки должны уместиться в 2052 ключа. Другие модели с полными слоями внимания берут ту же команду со
своей моделью; замерена только Qwen3.8-27B.

`scripts/dory/q27_final.sh` и `q27_quality.sh` снимают таблицы выше, `q27_figures.py` рисует рисунки, а в
`JOURNAL_Q27_TURBO_2026-11-05.md` записано, что пробовали.

## Что не вошло

- Дальнее поле работает на Vulkan, DX12 и Metal (`gpu_metal/o1c.rs`). На CPU файл идёт как обычный. Замеры сделаны на карте NVIDIA и на M4.
- За местом запечатывания текст приближённый: далёкое блекнет, кроме строк, оставленных точными. Модель видела вставленные
  факты; другие виды важного текста не проверялись.
- Строки, пришедшие после конца промпта, остаются в окне или уходят в дальнее поле. Ход, который расходится с запечатанным
  разговором, читает весь промпт заново.
- На Vulkan черновикам нужно жадное декодирование без штрафов.
- Генерация, начатая ниже места запечатывания, остаётся точной, и её память растёт с каждым токеном.
