# Навыки поверх замороженного ствола на Embryo-56M

Вопрос владельца, 17.11.2026: как работает лёгкое наложение навыков на Embryo-56M —
наложить один навык, запечь, наложить второй, запечь и посмотреть, насколько модель
поумнеет.

## Постановка

- Модель: релизный Embryo-56M (`~/embryo-data/o1/chat-sft/keep-final-healed.ckpt`, 55,9 млн
  параметров, 8 слоёв × 384, в каждом слое общий FFN и 4 эксперта, выбор эксперта по ошибке
  реконструкции).
- Наложение — собственный механизм Embryo: `cortiq-embryo grow`. В каждый слой добавляется K
  экспертов, учатся только они, ствол и прежние эксперты заморожены.
- Запекание — выращенный геном целиком (`grow --out-ckpt`, затем `export`): новые эксперты
  становятся частью модели, следующий навык растёт уже поверх него.
- Навык 1, «команда по карточке»: 67 222 задачи `stage0/train_gen.py` (slot, direct, choose,
  os, fix, none, two) как разговоры в рамке cmf-im-v1; отложена одна страница tldr из 20
  (3394 задачи). Это тот же набор, на котором на этапе 0 дообучался весь ствол.
- Навык 2, «действие по правилам»: 5985 задач react с ответом после дословно переписанного
  правила (`stage0/lookup_gen.py --reason react --labels --or-rules 0.25`); отложена каждая
  двадцатая (315).
- Мерило: набор R (362 задачи, карточка в запросе, без примеров, оценка в песочнице; команды
  и пути R в обучении отсутствуют) и перплексия обычного текста (`~/embryo-data/heldout-en.txt`,
  16 окон по 512 токенов). Скрипты: `build_corpus.py`, `grow_skill.sh`, `measure.sh`.

Для сравнения, этап 0 (дообучение всего ствола на том же наборе, батч 5 × 512, lr 1e-4):

| | R | Обычный текст, NLL |
|---|---|---|
| Релиз | 0/362 | 4,08 |
| 500 шагов | 34/362 | 4,24 |
| 1000 шагов | 46/362 | 4,33 |
| 2000 шагов | 39/362 | 4,48 |

## Ход

### Исходная модель

`m0` — релиз, f16: R 0/362, перплексия обычного текста 46,09. Ответы длиной до 96 токенов (на
этапе 0 было 48: задачам с правилами нужно место под рассуждение).

### Точка сравнения: рост экспертами (`grow`)

Первое прочтение задачи: наложение — рост экспертами, собственный механизм Embryo. Владелец
уточнил, что имел в виду маску DTG-MA с коррекцией FCD (`skill-bake`); прогон оставлен как
точка сравнения.

`grow_skill.sh a1 keep-final-healed.ckpt skill1 2 1500`: по 2 новых эксперта в каждом из 8
слоёв (+14,2 млн параметров, активных на токен столько же, сколько было: 34,7 млн), 1500
шагов 4 × 512, учатся только новые эксперты, потери — по всему тексту разговора.

| | R | Обычный текст, перплексия |
|---|---|---|
| Релиз | 0/362 | 46,09 |
| + навык 1 ростом, геном целиком | **51/362 (14,1 %)** | 47,97 (+4,1 %) |

- По категориям: slot 23/128, os 6/59, choose 7/28, none 8/16, direct 5/20, react 1/25, two
  1/27, fix 0/19, arith 0/40.
- Потери на отложенных страницах 4,12 → 1,99 (−52 %); 0,5 с на шаг, весь рост 13 минут вместе
  с трассировкой.
- Больше, чем дообучение всего ствола на том же наборе (34–46 из 362), при том что обычный
  текст почти цел: перплексия +4 %. У ствола после 2000 шагов дообучения
  (`ft56b5-2000.ckpt`) на том же тексте 76,70 — +66 %.
- Без оболочек новые эксперты выигрывают 36,9 % токенов обычного текста, с оболочками записи —
  5,8 %. Замер сделан на геноме целиком, без оболочек.

### Навык 1 через `skill-bake` с настройками тренера Embryo: не та методика

Уточнение владельца: наложение — это маска DTG-MA с коррекцией FCD, как в релизе 0.9.3 для
CUDA.

`cortiq-embryo skill-bake` (v2) в исходном виде: жёсткая маска 1[σ(m) > τ] на нейронах общего
FFN выбранных слоёв под растущим L1 (фаза A), затем дообучение этих FFN под маской (фаза B);
запись `ffn_replace` дописывается в копию файла генома, геном не меняется; какой запрос идёт
в навык, решает роутер по φ. Входы готовит `build_sft.py`, запуск — `bake_skill.sh`.

`bake_skill.sh b1 f0 s1 cards --batch 16 --lm-frac 0.25 --steps-a 600 --steps-b 120
--eval-every 60 --dev-batches 16`, слои 6 и 7 (без `--dev-batches` каждая проверка идёт по
всем 5976 отложенным записям: девять минут до первого шага):

| | Потери на ответах (отложенные) | Обычный текст, NLL | Оставлено нейронов |
|---|---|---|---|
| Геном | 2,167 | 3,275 | 100 % / 100 % |
| Маска, лучший шаг 540 | 1,856 | 3,328 | 46 % / 79 % |
| + дообучение FFN, 120 шагов | 1,608 | 3,324 | те же |

- С принудительно включённым навыком (`--route cards`): **R 9/362** — slot 4, none 4, direct 1.
- Запись выходит со статусом «карантин» и до ворот (`route-eval` + `skill-gate`) роутером не
  используется: `--route auto` даёт те же 0/362, что геном. Роутер свои запросы узнаёт в
  98,0 %, ложных срабатываний на общих вопросах 0 из 85.

Это не методика релиза 0.9.3, и следующий шаг, который я запустил (четыре слоя, 1200 шагов
фазы B), уводил от неё ещё дальше; владелец остановил: «какие 1200 шагов FCD». Остановлено
на первых минутах.

### Методика релиза 0.9.3 и чего не хватало тренеру Embryo

По `scripts/skill-cuda/pod/*.sh` (навык эмоций, `cortiq skill bake`, A40):

- Фаза A: маска на нейронах FFN всех слоёв, начальный логит 4,0 (σ = 0,982), lr 0,05, **без
  L1** (`--l1-init 0 --l1-step 0`), потери только на ответе, 500 шагов на 0,8B и 1000 на 4B при
  батче 64 и 32 коротких записей, проверка каждые 100 шагов с сохранением маски. Маска
  остаётся мягкой: вес нейрона σ(m) сворачивается в down_proj (`--soft-fold`).
- Чекпойнт маски выбирается по точности ответа, а не по перплексии: на 4B 1500 шагов дали
  перплексию ниже, а точность 68,5 % против 69,8 % на 1000.
- Фаза B, FCD: от выбранной маски 2 шага на 2 последних слоях с lr 1e-6 (3e-6 на 4B вредит),
  проверка после каждого шага; берётся, только если лучше одной маски.
- Итог там: 0,8B 38,3 → 64,1 % (маска), 4B 55,7 → 69,8 % (маска) → 71,0 % (+FCD). Навык кода
  перплексию почти не сдвинул: маска знаний не добавляет.

`cortiq skill bake` архитектуру Embryo не принимает (у Embryo общий FFN плюс эксперты, другие
имена тензоров). В запекание тренера Embryo перенесено (`skill.rs`, `model.rs`, `main.rs`;
без новых опций поведение прежнее):

- `--soft-fold`: маска оценивается, дообучается и сворачивается как σ(m) (столбцы down_proj
  умножаются на вес нейрона), а не как жёсткая;
- `--mask-init` (по умолчанию прежние 3,0);
- `--fcd-layers N`: фаза B учит только N последних из выбранных слоёв;
- `--eval-every-b`: проверка в фазе B со своим шагом (для FCD в 2 шага — после каждого).

Отличие, которое осталось: тренер Embryo выбирает точку по потерям на ответах отложенного
набора, счёта точности в нём нет.

### Навык 1 по методике: мягкая маска на семи слоях, FCD в два шага

--fcd-layers 2 --eval-every-b 1 --batch 16 --dev-batches 16`. Нулевой слой оставлен роутеру
(φ берётся после него). Обучаемых чисел в фазе маски 7 × 768 = 5376.

| Шаг маски | 0 | 100 | 200 | 300 | 400 | 500 | 600 | 700 | 1000 | + FCD, 2 шага |

- На итоговом отложенном наборе (6625 записей) 2,175 → 1,109. Обычный текст под навыком:

- FCD в два шага с lr 1e-6 почти ничего не добавляет (1,1230 → 1,1228), как и в релизе 0.9.3:

### Скорость запекания на Маке

Вопрос владельца: почему так долго, оптимизирован ли процесс на GPU. Шаг запекания идёт на GPU
(Metal) целиком; 1,9 с на шаг при 16 × 512 токенов — 4,3 тыс. ток/с, это скорость самого
тренера Embryo на M4 (дообучение ствола: 0,45 с на 5 × 512, 5,7 тыс. ток/с). Потери были в
другом:

- **Оценка итогового набора целиком до обучения и после него**: 6625 записей × 2 — 7,5 минуты
  на каждое запекание из 45. Добавлен `--final-batches` (как `--dev-batches`): до первого шага
  268 с → 35 с. Без опции числа прежние до последнего знака (потери шагов и отложенные NLL
  короткого прогона совпали со сборкой до правки).
- **Добивка записей до ширины шарда**: медиана задачи 212 токенов при ширине 512. Добавлен
  `--length-buckets` (`--bucket-widths`): батч берётся из записей одного класса длины и
  считается на копии модели этой ширины; состояние маски переносится между копиями.
  Точность проверена: 16 записей дают одни и те же потери на своей ширине и на 512 (2,775647,
  1,979920, 2,449012 для ширин 192, 256, 384). Но каждая ширина — отдельная копия со своими
  буферами: три копии рядом с батчем 16 × 512 в 24 ГБ Мака не помещаются, шаг вместо 1,9 с
  шёл 4,7 с и дальше хуже. На Маке опция не используется; смысл в ней есть на карте с запасом
  памяти.
- Для навыка с короткими записями шарды готовятся сразу узкими: правила целиком помещаются в
  256 токенов (максимум 208), шаг вдвое дешевле.
- Запекание работает и на CUDA: бэкенд `cuda` тренера — тот же записанный набор операций, что
  у Vulkan и Metal, новые опции от бэкенда не зависят. На A40 не запускалось: карта занята
  базой 340M.
- Ловушка: два запекания одновременно на Маке не идут. Пробный прогон рядом с основным
  остановил оба (память), замер скорости рядом с прогоном R на процессоре испорчен.

Куда роутер отправил задачи: карточные категории — в `cards` 291 из 297 (6 в геном), правила —
в `rules` 21 из 25 (4 в геном), расчёты — в геном 38 из 40.

- Второй навык не испортил первый: карточные категории дали те же числа, что с одним навыком.
  Записи независимы, геном заморожен.

- Навык из 5376 чисел поднимает модель с 0 до 30 задач из 362 на командах, которых в обучении
  не было. Дообучение всех 55,9 млн параметров давало 34–46 и портило обычный текст (76,70).
- Правила: 6 из 25 при потерях на ответах 0,82. Ответ там — дословная копия правила; на
  340M это заработало только на базе.

Чего методике не хватает в тренере Embryo:

- Маска стоит только на общем FFN слоя (768 нейронов); четыре эксперта слоя, из которых на
  каждом токене работает один, маской не покрыты. Слой 0 оставлен роутеру.
- Точка выбирается по потерям на ответах, а не по точности.
- К шагу 1000 маска навыка 1 ещё медленно улучшалась.
